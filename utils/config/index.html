    config.py 文件详解¶

    文件路径：src/runtime/config.py

    这个文件是 MAGIC 系统的运行时配置管理模块，负责加载、验证和管理 Agent 的配置。

    数据类¶

    RuntimeConfig¶

    定义位置：第 118-197 行

    单个模式的运行时配置数据结构。包含了 Agent 运行所需的所有核心配置。

    核心字段：

    字段类型 字段名 说明
    基础信息 version, name, hertz 版本、名称、执行频率
    系统提示词 system_prompt_base, system_governance, system_prompt_examples 基础提示词、治理规则、示例
    组件 agent_inputs, cortex_llm, simulators, agent_actions, backgrounds 输入传感器、LLM、模拟器、动作、后台进程
    可选参数 api_key, robot_ip, URID, unitree_ethernet, mode API密钥、机器人配置、模式名
    动作控制 action_execution_mode, action_dependencies, action_gate 动作执行模式、依赖关系、安全门控
    语音规划 voice_planner_llm, voice_planner_runtime 语音任务分解 LLM 及运行时配置
    硬件自检 hardware_preflight 启动时硬件探测配置
    知识库 knowledge_base 文档检索知识库配置
    MCP mcp_servers MCP 服务器实例

    ModeConfig¶

    定义位置：第 295-490 行

    单个模式的详细配置。

    核心字段：

    字段 类型 说明
    version str 模式配置版本
    name / display_name / description str 模式标识与描述
    system_prompt_base str 模式系统提示词
    hertz float 执行频率，默认 1.0
    timeout_seconds Optional[float] 模式超时时间
    remember_locations bool 是否记住位置
    save_interactions bool 是否保存交互记录
    lifecycle_hooks List[LifecycleHook] 模式生命周期钩子
    agent_inputs List[Sensor] 已加载的输入传感器实例
    cortex_llm Optional[LLM] 模式 LLM
    agent_actions List[AgentAction] 已加载的动作实例
    backgrounds List[Background] 已加载的后台进程实例
    action_execution_mode Optional[str] 动作执行模式（concurrent/sequential/dependencies）
    action_dependencies Optional[Dict] 动作依赖关系
    action_gate Optional[Dict] 模式级安全门控
    hardware_preflight Optional[Dict] 硬件自检配置
    voice_planner_llm Optional[LLM] 模式级语音规划 LLM
    voice_planner_runtime Optional[Dict] 语音规划运行时配置
    mcp_servers Optional[Any] MCP 服务器实例

    原始配置字段（用于延迟加载与序列化）：

    字段 说明
    _raw_inputs 原始输入配置列表
    _raw_llm 原始 LLM 配置
    _raw_voice_planner_llm 原始语音规划 LLM 配置
    _raw_simulators 原始模拟器配置列表
    _raw_actions 原始动作配置列表
    _raw_backgrounds 原始后台进程配置列表
    _raw_lifecycle_hooks 原始生命周期钩子配置列表
    _raw_mcp_servers 原始 MCP 服务器配置列表

    关键方法：

    方法名 说明
    to_runtime_config(global_config) 将模式配置转换为运行时配置，合并全局治理规则、api_key 等
    load_components(system_config) 加载模式所需的实际组件实例（延迟加载）
    execute_lifecycle_hooks(hook_type, context) 异步执行该模式的生命周期钩子

    ModeSystemConfig¶

    定义位置：第 493-618 行

    完整的模式系统配置，管理多个模式及其切换规则。

    核心字段：

    字段 类型 说明
    version / name str 系统版本与名称
    default_mode str 默认启动模式
    config_name str 配置文件名
    allow_manual_switching bool 是否允许手动切换模式，默认 True
    mode_memory_enabled bool 是否启用模式记忆，默认 True
    api_key / robot_ip / URID / unitree_ethernet Optional[str] 全局参数
    system_governance / system_prompt_examples str 全局治理规则和示例
    knowledge_base Optional[Dict] 知识库配置
    mode_router_llm Optional[LLM] 模式路由 LLM（决定何时切换模式）
    mode_router Optional[Dict] 模式路由运行时配置
    voice_task_planner_llm Optional[LLM] 全局语音任务分解 LLM
    voice_task_planner Optional[Dict] 语音任务规划运行时配置
    global_cortex_llm Optional[Dict] 全局默认 LLM 配置（模式未覆盖时使用）
    global_lifecycle_hooks List[LifecycleHook] 全局生命周期钩子（所有模式共享）
    modes Dict[str, ModeConfig] 模式名 → ModeConfig 映射
    transition_rules List[TransitionRule] 模式切换规则列表

    关键方法：

    方法名 说明
    execute_global_lifecycle_hooks(hook_type, context) 执行全局生命周期钩子

    TransitionRule¶

    定义位置：第 260-292 行

    定义模式间切换规则的数据类。

    核心字段：

    字段名 类型 说明
    from_mode str 源模式名称
    to_mode str 目标模式名称
    transition_type TransitionType 切换类型
    trigger_keywords List[str] 触发关键词列表
    priority int 优先级（数字越大优先级越高）
    cooldown_seconds float 冷却时间（秒）
    timeout_seconds Optional[float] 超时时间（秒）
    context_conditions Dict 上下文条件

    TransitionType¶

    定义位置：第 244-258 行

    枚举类，定义四种模式切换类型。

    枚举值 说明
    INPUT_TRIGGERED 基于输入关键词触发
    TIME_BASED 基于时间触发
    CONTEXT_AWARE 基于上下文触发
    MANUAL 手动触发

    核心函数¶

    _load_schema¶

    定义位置：第 34-59 行

    作用：加载并缓存 JSON Schema 文件用于配置验证。

    流程： 1. 从 ../../config/schema/ 目录加载指定的 schema 文件 2. 文件不存在时抛出 FileNotFoundError 3. 返回解析后的 schema 字典

    validate_config_schema¶

    定义位置：第 62-87 行

    作用：验证配置字典是否符合预定义的 Schema。

    流程： 1. 根据配置中是否包含 modes 和 default_mode 字段，选择多模式或单模式 schema 2. 调用 _load_schema 加载对应 schema 3. 使用 jsonschema.validate() 进行验证 4. 验证失败时，记录详细的错误字段路径并抛出异常

    _read_system_prompt_path¶

    定义位置：第 90-97 行

    作用：读取系统提示词文件内容。

    流程： 1. 展开路径中的环境变量和用户目录符号（~） 2. 如果是相对路径，转换为相对于配置文件的绝对路径 3. 读取文件内容并去除尾部换行符

    _apply_system_prompt_path¶

    定义位置：第 100-104 行

    作用：将配置段中的 system_prompt_path 字段转换为 system_prompt_base 字段。

    apply_system_prompt_paths¶

    定义位置：第 107-115 行

    作用：递归处理所有系统提示词路径。对多模式配置遍历所有 mode，对单模式配置直接处理。

    add_meta¶

    定义位置：第 199-241 行

    作用：将全局元数据（API密钥、机器人配置、模式名等）注入到组件配置中。

    处理字段：api_key、unitree_ethernet、URID、robot_ip、mode

    特点：仅在配置中不存在对应字段时才添加全局值（不覆盖已有配置）。

    load_mode_config¶

    定义位置：第 621-761 行

    作用：主入口函数，从 JSON5 文件加载完整的模式系统配置。

    参数： - config_name: str — 配置文件名（不含 .json5 扩展名） - mode_source_path: Optional[str] — 自定义配置文件路径（可选）

    返回值： - ModeSystemConfig — 完整的模式系统配置对象

    流程：

    1. 构建配置文件路径（默认为 ../../config/<name>.json5）
   ↓
2. 解析 JSON5 文件
   ↓
3. 验证运行时版本 (verify_runtime_version)
   ↓
4. 加载环境变量 (load_env_vars)
   ↓
5. 应用系统提示词路径 (apply_system_prompt_paths)
   ↓
6. 验证配置 schema (validate_config_schema)
   ↓
7. 转换为多模式格式 (convert_to_multi_mode)
   ↓
8. 提取全局参数（api_key, robot_ip, URID, unitree_ethernet）
   ↓
9. 初始化 Unitree 机器人 (load_unitree)
   ↓
10. 创建 ModeSystemConfig 对象，包含：
    - 全局字段（name, default_mode, system_governance 等）
    - knowledge_base, mode_router, voice_task_planner 配置
    - global_cortex_llm 默认 LLM 配置
    - 解析 global_lifecycle_hooks
    ↓
11. 加载全局 mode_router_llm（如果配置）
    ↓
12. 加载全局 voice_task_planner_llm（如果配置）
    ↓
13. 遍历 modes 创建所有 ModeConfig 对象，包含：
    - lifecycle_hooks 解析
    - hardware_preflight 配置
    - voice_planner_runtime 配置
    - 所有 _raw_* 原始配置字段
    ↓
14. 解析所有 TransitionRule 规则
    ↓
15. 返回完整的 ModeSystemConfig 对象

    调用的关键函数： - verify_runtime_version() - load_env_vars() - apply_system_prompt_paths() - validate_config_schema() - convert_to_multi_mode() - load_unitree() - parse_lifecycle_hooks() - load_llm()

    _load_mode_components¶

    定义位置：第 764-890 行

    作用：为特定模式加载实际的组件实例（延迟加载，在模式激活时调用）。

    加载的组件：

    组件类型 加载函数 存储字段
    输入传感器 load_input() agent_inputs
    模拟器 load_simulator() simulators
    动作 load_action() agent_actions
    后台进程 load_background() backgrounds
    主 LLM load_llm() cortex_llm
    语音规划器 LLM (模式级) load_llm() voice_planner_llm
    MCP 服务器 load_mcp() mcp_servers

    特点： - 每个组件加载时都会调用 add_meta 注入全局元数据（api_key, unitree_ethernet, URID, robot_ip, mode） - 主 LLM 优先使用模式级 _raw_llm，回退到全局 global_cortex_llm - 语音规划 LLM 优先使用模式级 _raw_voice_planner_llm

    mode_config_to_dict¶

    定义位置：第 893-971 行

    作用：将 ModeSystemConfig 对象序列化回字典格式（用于持久化和调试）。

    序列化内容： - 全局字段（version, name, default_mode 等） - knowledge_base, mode_router, voice_task_planner 配置 - 每个 mode 的完整配置（包括 name, display_name, system_prompt_base, action_gate, hardware_preflight, voice_planner_llm, voice_planner_runtime 等） - 所有 transition_rules

    辅助模块¶

    env.py — 环境变量加载¶

    文件路径：src/runtime/env.py

    EnvLoader 类提供配置中 ${ENV_VAR} 和 ${ENV_VAR:-default} 模式的环境变量替换。

    核心方法：

    方法 说明
    load_env_vars(config) 递归处理整个配置 dict/list/str，替换其中的环境变量模式
    load_value(value) 对单个字符串进行替换，支持 ${VAR} 和 ${VAR:-default} 语法

    实现细节： - 正则模式：\$\{([^}:]+)(?::-([^}]*))?\} - 先查环境变量，若不存在则用默认值，若都没有则保留原字符串并警告 - 对外暴露 load_env_vars = EnvLoader.load_env_vars 模块级函数

    converter.py — 单模式转多模式¶

    文件路径：src/runtime/converter.py

    ConfigConverter 类将旧版单模式 JSON5 配置自动转换为多模式格式，实现向后兼容。

    核心方法：

    方法 说明
    is_single_mode(raw_config) 检测是否缺少 modes 或 default_mode 字段
    convert_to_multi_mode(raw_config) 主转换入口，已多模式则直接返回
    _build_global_section(raw_config, mode_name) 构建全局字段（version, name, api_key, system_governance, knowledge_base, mode_router, voice_task_planner, cortex_llm 等）
    _build_mode_section(raw_config) 构建模式字段（display_name, hertz, agent_inputs, agent_actions, backgrounds, action_gate, hardware_preflight, mcp_servers 等）
    _validate(converted_config, mode_name) 验证转换后的结构完整性

    转换逻辑： - 原 name → default_mode + mode key - 原顶层 LLM → 全局 cortex_llm（模式无覆盖时作为默认） - allow_manual_switching 和 mode_memory_enabled 默认设为 False（保持单模式行为） - 对外暴露 convert_to_multi_mode = ConfigConverter.convert_to_multi_mode

    version.py — 版本校验¶

    文件路径：src/runtime/version.py

    定义了运行时版本管理与兼容性校验逻辑。

    当前运行时版本：v1.0.3

    函数 说明
    get_runtime_version() 返回当前运行时版本字符串
    is_version_supported(version) 检查配置版本是否兼容（主版本号必须一致，次版本号不一致仅警告）
    verify_runtime_version(config_version, config_name) 包装 is_version_supported，提供日志和错误上下文

    hook.py — 生命周期钩子¶

    文件路径：src/runtime/hook.py

    定义了生命周期钩子的配置模型、解析逻辑和执行引擎。

    LifecycleHookType 枚举：

    枚举值 触发时机
    ON_ENTRY 进入模式时
    ON_EXIT 退出模式时
    ON_STARTUP 系统启动时
    ON_SHUTDOWN 系统关闭时
    ON_TIMEOUT 模式超时时

    LifecycleHook 数据类字段：

    字段 类型 说明
    hook_type LifecycleHookType 钩子类型
    handler_type str 处理器类型：message、command、function、action
    handler_config Dict 处理器配置
    async_execution bool 是否异步执行，默认 True
    timeout_seconds Optional[float] 超时时间，默认 5.0s
    on_failure str 失败策略：ignore（默认）或 abort
    priority int 同类型钩子的执行优先级（高优先执行）

    四种 Handler：

    Handler 配置类 说明
    MessageHookHandler MessageHookConfig 日志记录或 TTS 语音播报消息，支持 {variable} 格式化。TTS 支持 elevenlabs、kokoro、riva、qwen 四种后端
    CommandHookHandler CommandHookConfig 执行 shell 命令，通过 asyncio.create_subprocess_shell 运行
    FunctionHookHandler FunctionHookConfig 调用 hooks/ 目录下 Python 模块中的函数，支持异步和同步函数
    ActionHookHandler ActionHookConfig 动态加载并执行 Agent 动作

    关键函数：

    函数 说明
    parse_lifecycle_hooks(raw_hooks, api_key) 将 JSON5 原始配置解析为 List[LifecycleHook]，自动注入 api_key
    execute_lifecycle_hooks(hooks, hook_type, context) 按 priority 降序执行同类型钩子，处理超时和 abort 策略
    create_hook_handler(hook) 根据 handler_type 创建对应的 handler 实例

    hardware_preflight.py — 硬件自检¶

    文件路径：src/runtime/hardware_preflight.py

    启动时探测硬件可用性，自动禁用缺失硬件对应的 input、background 和 action。

    核心数据结构：

    类 说明
    HardwareCheck 单次硬件探测结果（name, passed, detail）
    HardwarePreflightReport 自检汇总（checks, available_capabilities, disabled_inputs, disabled_backgrounds, disabled_actions）

    核心函数：

    函数 说明
    apply_hardware_preflight(mode_config, probe) 主入口：探测硬件 → 从 _raw_inputs/_raw_backgrounds/_raw_actions 中移除对应组件 → 返回 report
    format_hardware_preflight_report(report) 将报告格式化为中文 LLM 提示词文本

    硬件探测逻辑（HardwarePreflightProbe 类）：

    方法 说明
    has_realsense_device(serial_number) 通过 pyrealsense2 库查询 D435/D435i 相机是否在线，支持按序列号精确匹配
    has_fresh_arx_state(topic, timeout_seconds, max_age_seconds) 通过 Zenoh 订阅 ARX X5 机械臂状态 topic，判断是否有新鲜数据

    探测来源：

    1. 显式 capabilities 配置：JSON5 中 hardware_preflight.capabilities 声明的能力及其 probe 类型（realsense、zenoh_state）
    2. D435 Background 自动探测：遍历 backgrounds 中的 D435 类型，按 enable_realsense_capture 和 serial_number 探测
    3. ARX X5 运动探测：检测 action 中是否有 arm_x5_reset、arm_x5_joint_nudge、hello 或 grasp_object 标签，若有则自动探测 ARX 状态

    组件过滤规则：

    组件类型 过滤条件
    D435RealSenseInput camera_id 对应的 D435 不可用则移除
    其他 Input 检查 requires_capabilities 字段
    D435 Background camera_id 对应的 D435 不可用则移除
    ARXX5YoloGraspExecutor Background ARX 不可用则移除
    grasp_object Action ARX 不可用或 grasp camera 不可用则移除
    arm_x5_* / hello Action ARX 不可用则移除

    核心设计理念¶

    1. 延迟加载¶

    组件实例不在配置解析时立即加载，而是在模式激活时通过 load_components() 调用 _load_mode_components() 加载，避免单例冲突。

    # 配置解析阶段：只存储原始配置 (_raw_* 字段)
mode_config = ModeConfig(
    _raw_inputs=mode_data.get("agent_inputs", []),
    _raw_llm=mode_data.get("cortex_llm"),
    _raw_actions=mode_data.get("agent_actions", []),
    ...
)

# 模式激活阶段：加载实际组件
mode_config.load_components(system_config)

    2. 配置继承¶

    模式可使用全局默认配置，也可覆盖。

    # LLM 配置优先级：模式级 > 全局默认
llm_config = mode_config._raw_llm or system_config.global_cortex_llm

# 语音规划器 LLM：模式级覆盖全局级
if mode_config._raw_voice_planner_llm:
    mode_config.voice_planner_llm = load_llm(...)

    3. Schema 验证¶

    确保配置文件格式正确，在运行前捕获配置错误。

    validate_config_schema(raw_config)  # 使用 JSON Schema 验证
# 自动选择 single_mode_schema.json 或 multi_mode_schema.json

    4. 环境变量支持¶

    通过 EnvLoader 递归处理所有字符串值，支持 ${VAR} 和 ${VAR:-default} 语法。

    5. 模式切换¶

    支持多种切换触发机制和优先级规则： - INPUT_TRIGGERED：关键词触发 - TIME_BASED：定时触发 - CONTEXT_AWARE：上下文感知 - MANUAL：手动切换

    6. 硬件自检¶

    启动时自动探测硬件（D435 相机、ARX 机械臂），不可用时自动禁用相关组件，避免运行时崩溃。

    7. 单模式向后兼容¶

    旧版单模式 JSON5 配置通过 ConfigConverter 自动转换为多模式格式，无需手动迁移。

    raw_config = convert_to_multi_mode(raw_config)
# 原单模式: {name: "xxx", agent_inputs: [...], ...}
# 转换后: {default_mode: "xxx", modes: {"xxx": {...}}, ...}

    典型使用示例¶

    from runtime.config import load_mode_config

# 加载配置
config = load_mode_config("unitree_go2_koala_nav_vision_no_arm")

# 访问配置信息
print(f"Default mode: {config.default_mode}")
print(f"Available modes: {list(config.modes.keys())}")

# 激活某个模式时加载组件
mode = config.modes[config.default_mode]
mode.load_components(config)

# 转换为运行时配置
runtime_config = mode.to_runtime_config(config)
