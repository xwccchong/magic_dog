    Orchestrator 启动机制详解¶

    cortex.py 中的 _start_orchestrators() 是整个系统的七路并发起点。它同时启动 Input、Action、Background、Simulator、MCP、CortexLoop、ModeTransition 七个异步任务。

    一、_start_orchestrators() — 七路并发枢纽¶

    位于 cortex.py:502：

    async def _start_orchestrators(self):
    if not self.current_config:
        raise RuntimeError("No current config available")

    # 0. 重置休眠标志 (mode 切换时被设为 skip)
    self.sleep_ticker_provider.skip_sleep = False

    # 1. 创建 InputOrchestrator，启动所有 input 的异步 listen 循环
    self.input_orchestrator = InputOrchestrator(self.current_config.agent_inputs)
    self.input_listener_task = asyncio.create_task(
        self.input_orchestrator.listen()
    )

    # 2-4. 条件启动其他 Orchestrator (都是 asyncio 兼容的 Future)
    if self.simulator_orchestrator:
        self.simulator_task = self.simulator_orchestrator.start()
    if self.action_orchestrator:
        self.action_task = self.action_orchestrator.start()
    if self.background_orchestrator:
        self.background_task = self.background_orchestrator.start()

    # 5. MCP Server 启动
    if self.mcp_orchestrator:
        await self.mcp_orchestrator.start()

    # 6. 启动核心 tick 循环 ← 整个系统的心脏！
    self.cortex_loop_task = asyncio.create_task(self._run_cortex_loop())

    # 7. 启动模式切换处理器
    if not self.mode_transition_task or self.mode_transition_task.done():
        self.mode_transition_task = asyncio.create_task(self._handle_mode_transitions())

    二、BackgroundOrchestrator — 线程池驱动后台任务¶

    为什么用线程池而不是 asyncio？¶

    Background 任务（如 D435 相机采集 wait_for_frames()）是阻塞调用，不能在 asyncio event loop 中运行。ThreadPoolExecutor 提供独立线程管理。

    完整代码¶

    class BackgroundOrchestrator:
    def __init__(self, config: RuntimeConfig):
        self._config = config
        # 最多 12 个线程，至少 1 个
        self._background_workers = (
            min(12, len(config.backgrounds)) if config.backgrounds else 1
        )
        self._background_executor = ThreadPoolExecutor(
            max_workers=self._background_workers,
        )
        self._background_instances = []
        self._stop_event = threading.Event()

    def start(self) -> asyncio.Future:
        """提交所有 Background 到线程池"""
        for background in self._config.backgrounds:
            # 防重复提交
            if any(bg.name == background.name
                   for bg in self._background_instances):
                logging.warning(
                    f"Background {background.name} already submitted, skipping."
                )
                continue

            # 把同一个 stop_event 传给每个 Background
            background.set_stop_event(self._stop_event)

            # 提交到线程池
            self._background_executor.submit(
                self._run_background_loop, background
            )
            self._background_instances.append(background)

        return asyncio.Future()

    def _run_background_loop(self, background: Background):
        """每个 Background 的独立线程循环"""
        while not self._stop_event.is_set():
            try:
                background.run()       # ← 调用具体的 Background.run()
            except Exception:
                logging.exception(f"Error in background {background.name}")
                self._stop_event.wait(timeout=0.1)  # 出错等一下再重试

    def stop(self):
        """优雅停止所有 Background"""
        self._stop_event.set()          # 通知所有循环退出

        for background in self._background_instances:
            try:
                background.stop()       # 每个 Background 的清理
            except Exception:
                logging.exception(
                    f"Error stopping background {background.name}"
                )

        self._background_executor.shutdown(wait=True)  # 等待所有线程结束
        self._background_instances.clear()

    Background 基类¶

    class Background:
    def __init__(self, config):
        self.config = config
        self.name = getattr(config, "name", type(self).__name__)
        self._stop_event = None

    def set_stop_event(self, stop_event):
        self._stop_event = stop_event

    def should_stop(self) -> bool:
        return self._stop_event is not None and self._stop_event.is_set()

    def sleep(self, duration: float) -> bool:
        """休眠但可被 stop_event 提前唤醒"""
        if self._stop_event is None:
            time.sleep(duration)
            return True
        was_stopped = self._stop_event.wait(timeout=duration)
        return not was_stopped

    def run(self):
        """子类覆盖，默认每 60s 执行一次"""
        self.sleep(60)

    def stop(self):
        """子类覆盖，清理资源"""
        pass

    为什么用 Bridge 子进程？¶

    原因 说明
    GIL pyrealsense2.wait_for_frames() 每 66ms 持有 GIL 30-50ms，会阻塞 asyncio event loop 和所有其他线程
    conda 环境隔离 pyrealsense2 需要特定 conda 环境，而主进程在 .venv 中，两者 Python 版本/库版本不同
    错误隔离 相机断连或崩溃只影响子进程，主进程的 bridge loop 检测到退出后会记录错误，不影响 LLM/ASR
    文件交换 vs IPC 文件系统零依赖、原子写入、调试友好、跨任意 Python 版本

    四、InputOrchestrator — 异步轮询引擎¶

    完整代码¶

    class InputOrchestrator:
    def __init__(self, inputs: Sequence[Sensor]):
        self.inputs = inputs
        # 例如: [D435RealSenseInput, QwenRealtimeASRInput, UnitreeGo2Odom,
        #         UnitreeGo2Battery, FacePresence, GalleryIdentities, SelfieStatus]

    async def listen(self) -> None:
        """为每个 input 创建一个独立的 asyncio Task，并发运行"""
        input_tasks = [
            asyncio.create_task(
                self._listen_to_input(input),
                name=f"input_{type(input).__name__}"
            )
            for input in self.inputs
        ]
        # 并发等待所有 input task
        results = await asyncio.gather(*input_tasks, return_exceptions=True)

        # 某个 input 出错不影响其他
        for i, result in enumerate(results):
            if isinstance(result, Exception):
                input_name = type(self.inputs[i]).__name__
                logging.error(f"Input {input_name} failed: {result}")

    async def _listen_to_input(self, input: Sensor) -> None:
        """单个 Input 的监听循环"""
        input_name = type(input).__name__
        try:
            # input.listen() 返回 AsyncIterator，不断 yield 原始数据
            async for event in input.listen():
                try:
                    # 原始数据 → 文本 → 存入内部 messages 列表
                    await input.raw_to_text(event)
                except Exception as e:
                    logging.error(f"Error processing event in {input_name}: {e}")
        except Exception as e:
            logging.error(f"Input {input_name} listener failed: {e}")
            raise

    def stop(self):
        """停止所有 input"""
        for input_source in self.inputs:
            try:
                input_source.stop()
            except Exception:
                logging.exception(
                    f"Error stopping input {type(input_source).__name__}"
                )

    Sensor.listen() 和 FuserInput._listen_loop()¶

    # inputs/base/__init__.py — Sensor 基类
class Sensor:
    async def listen(self) -> AsyncIterator[R]:
        async for event in self._listen_loop():
            yield event

# inputs/base/loop.py — FuserInput 的默认实现
class FuserInput(Sensor):
    async def _listen_loop(self) -> AsyncIterator[R]:
        while True:
            yield await self._poll()   # ← 子类必须实现

    数据如何汇入 Fuser¶

    每个 Input 的独立 Task:
  _poll() → raw_to_text(event) → self.messages.append(Message(...))
                                     │
                                     │ 数据已缓存，等待 LLM tick 消费
                                     ▼
主 cortex_loop._tick():
  Fuser.fuse(inputs, finished_promises)
    └─ for each input in agent_inputs:
         formatted_latest_buffer()
           ├─ 如果 messages 非空 → 取出 messages[-1]
           ├─ 如果 messages 为空 + hold_last_vision → 复读上一帧缓存
           ├─ 格式化为 "INPUT: Vision\n// START\n...\n// END\n"
           ├─ 写入 io_provider.add_input(key, text, timestamp)
           └─ 清空 self.messages

    两条时间线的并行¶

    Input 线程 (每个 Input 独立，不同频率):
│ poll │ sleep │ poll │ sleep │ poll │ sleep │ poll │ sleep │
   ↓              ↓              ↓              ↓
  数据入队       数据入队        数据入队       数据入队

Tick 循环 (cortex_loop, 由 hertz 配置控制，如 2Hz = 0.5s):
         │ tick │         │ tick │         │ tick │
           ↑                ↑                ↑
          Fuser.fuse()     Fuser.fuse()     Fuser.fuse()
          消费所有 messages 消费所有 messages 消费所有 messages

    Input 的 _poll() 频率和 tick 频率是解耦的。 这是整个系统弹性伸缩的核心：Input 采集频率可以独立调整，tick 频率由 hertz 配置控制，两者互不影响。

    实际运行的并发结构¶

    asyncio Event Loop
  │
  ├── Task: _listen_to_input(D435RealSenseInput)
  │     └── while True: yield await _poll()
  │           └── await asyncio.sleep(0.05)
  │               try: return message_buffer.get_nowait()   ← VLM 文本
  │
  ├── Task: _listen_to_input(QwenRealtimeASRInput)
  │     └── while True: yield await _poll()
  │           └── await asyncio.sleep(0.1)
  │               从 WebSocket/ASR 回调队列取文本
  │
  ├── Task: _listen_to_input(UnitreeGo2Odom)
  │     └── while True: yield await _poll()
  │           └── await asyncio.sleep(0.1)
  │               return self.odom.position   ← 读 Provider 内存
  │
  ├── Task: _listen_to_input(UnitreeGo2Battery)       ← 同上模式
  ├── Task: _listen_to_input(ChargingStatusUnitreeGo2) ← 同上
  ├── Task: _listen_to_input(FacePresence)             ← HTTP 轮询人脸服务
  ├── Task: _listen_to_input(GalleryIdentities)        ← HTTP 轮询人脸注册库
  └── Task: _listen_to_input(SelfieStatus)             ← 自拍状态

    每个 Input 的 _poll() 被设计为非阻塞：要么立即返回数据，要么 await asyncio.sleep() 短暂让出控制权。所有 Input 在一组 asyncio Task 中并发运行，任何一个慢了都不会阻塞其他 Input。

    五、Background 和 Input 的协作模式对比¶

    维度 Input 自驱动 Background 驱动
    Provider 创建者 Input 自己 Background
    启动方式 asyncio.create_task(input.listen()) ThreadPoolExecutor.submit(background.run())
    运行线程 asyncio event loop 独立线程池线程
    适用场景 轻量/异步数据源 (ASR, Odom, Battery) 阻塞/重IO (相机, LiDAR)
    数据流向 Input._poll() → messages → Fuser Background 初始化 Provider → Input 读 Provider → messages → Fuser
    并发控制 asyncio 协程 (合作式) threading (抢占式)
