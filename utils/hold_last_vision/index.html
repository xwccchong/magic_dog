    hold_last_vision 机制详解¶

    问题本质：两条异步管线的速度差¶

    • 此时频率为2hz，所以一个tick是0.5s

    Camera → VLM 和 ASR 是两条完全独立的异步管线，它们的延迟不同步：

             Camera → VLM 管线                           ASR 管线
         ====================                         =========

t=0.0s   相机曝光 (66ms间隔)                         
t=0.1s   JPEG写入磁盘                                用户开始说话
t=0.2s   Bridge loop读取帧                           
t=0.3s   VLM worker编码base64                        声音持续采集
t=0.4s   HTTP请求发往DashScope                       
t=0.8s   VLM推理中...                               用户说完，VAD触发
t=1.2s   VLM返回结果 → message_buffer                 Voice输入就绪
         ↓
t=1.5s   Tick N: _poll()拿到VLM结果                   ← 但此时还没有Voice

t=2.0s   Tick N+1: Voice来了！但message_buffer为空     ← 新帧的VLM还没回来
         (hold_last_vision介入)

    核心矛盾：Camera → VLM 的延迟（采集 + JPEG编码 + HTTP请求 + 模型推理）通常需要 1-3 秒，而 ASR 的 VAD 触发是随时发生的。当用户说完话的那个 tick，可能恰好处于"VLM 还没回来"的时间窗口。

    hold_last_vision 的工作流程¶

    核心代码位于 D435RealSenseInput.formatted_latest_buffer()：

    def formatted_latest_buffer(self):
    now = time.time()

    if len(self.messages) == 0:                            # ← 本 tick 没有新 VLM 结果
        if (self.config.hold_last_vision                    # ← 配置开了 hold
            and self._held_vision_text                      # ← 有上一轮的缓存
            and self._held_vision_still_valid(now)):        # ← 还没过期 (<45s)

            # 复用上一帧的 VLM 文本
            body = self._held_vision_text                  # "画面中有一个红色瓶子，桌上..."
            self.io_provider.add_input("Vision", body, now)  # 重新注入 IOProvider
            return self._format_vision_block(body)          # 拼成 "INPUT: Vision\n..."
        return None                                         # 没缓存也没新数据 → 空

    # 有新消息：正常流程
    latest_message = self.messages[-1]
    self._held_vision_text = latest_message.message        # ← 存入缓存，供后续复用
    self._held_vision_at = now
    self.messages = []                                      # 清空队列
    return self._format_vision_block(latest_message.message)

    配置参数¶

    // D435RealSenseInput config
hold_last_vision: true,
hold_last_vision_max_age_seconds: 45,

    45 秒过期时间的选择¶

    过期时间 效果 问题
    太短 (2s) VLM 推理花了 3 秒 → 缓存已过期 → LLM 看不到视觉 失去 hold 的意义
    太长 (300s) 用户已走开，LLM 仍对 5 分钟前的画面说话 产生错误上下文
    45 秒 覆盖最坏情况的 VLM 延迟，同时保证场景未剧变 平衡点

    如果 45 秒内都没有新 VLM 帧到达，说明相机或 VLM 服务出问题了，此时继续复用旧数据会误导 LLM，不如返回空。

    具体时序示例¶

    Tick 1 (t=0.0s): Voice=无, Vision=新(VLM返回"桌上有一个红色瓶子")
  → formatted_latest_buffer() 正常路径
  → 返回 "INPUT: Vision\n桌上有一个红色瓶子..."
  → _held_vision_text = "桌上有一个红色瓶子"
  → _held_vision_at = 0.0

Tick 2 (t=0.5s): Voice=无, Vision=无(VLM还在推理中)
  → messages 为空, hold_last_vision=true, 缓存年龄=0.5s < 45s
  → 复用: 返回 "INPUT: Vision\n桌上有一个红色瓶子..."
  → LLM 看到 Voice=无 → 不动作 (符合 action_gate 规则)

Tick 3 (t=1.0s): Voice="那个瓶子是什么颜色？", Vision=无(VLM还在推理)
  → messages 为空, hold_last_vision=true, 缓存年龄=1.0s < 45s
  → 复用: 返回 "INPUT: Vision\n桌上有一个红色瓶子..."
  → LLM 看到 Voice + Vision → 回答 "它是一个红色瓶子。"
  ← 关键！没有 hold 机制，LLM 只能看到 Voice 没有 Vision

Tick 4 (t=1.5s): Voice=无, Vision=新(VLM返回"一只手指向瓶子")
  → 正常消费新消息
  → 更新 _held_vision_text = "一只手指向瓶子"

    没有 hold_last_vision 会怎样？¶

    Tick 3 (t=1.0s): Voice="那个瓶子是什么颜色？", Vision=无
  → formatted_latest_buffer() 返回 None
  → LLM prompt 中完全没有 Vision 段落
  → LLM 被迫回答 "抱歉，我目前看不到画面，无法判断瓶子的颜色。"
  → 用户困惑："你不是有摄像头吗？"

    与 action_gate 的配合¶

    hold_last_vision 和 action_gate 是两个独立但互补的机制：

    机制 作用 控制对象
    action_gate 没有新鲜 Voice → 不调用 LLM LLM 调用
    hold_last_vision 没有新鲜 Vision → 复用旧 Vision Vision 输入

    它们组合后的行为：

                     Voice有      Voice无
                 ────────     ───────
Vision有 (新鲜)  │ 正常调用    │ 正常调用(LLM看到无Voice则空输出)
Vision无 (复用)  │ hold复用    │ hold复用(但LLM看到无Voice则空输出)
Vision无 (过期)  │ 无Vision    │ 无Vision(LLM不调用)

    action_gate 保证了"没有语音时 LLM 不动作"，hold_last_vision 保证了"有语音时 LLM 总能拿到一个视觉上下文"。
