    Lifecycle Hooks 执行机制详解¶

    从 JSON5 配置到 TTS 声音播放的完整链路，涉及三个文件：

    • runtime/hook.py — 钩子系统全部逻辑（680 行）
    • runtime/config.py — 配置解析时调用 parse_lifecycle_hooks()
    • runtime/cortex.py — 启动时调用 execute_global_lifecycle_hooks()

    一、从 JSON5 配置到 LifecycleHook 对象¶

    以 unitree_go2_koala_welcome.json5 中的 on_startup 钩子为例：

    // config/unitree_go2_koala_welcome.json5 L170-183
lifecycle_hooks: [
    {
      hook_type: "on_startup",
      handler_type: "message",
      handler_config: {
        message: "你好，我是 Koala。你可以告诉我你的名字，或者直接说需要我帮什么。",
        tts_provider: "kokoro",
        base_url: "${KOKORO_BASE_URL:-http://127.0.0.1:8880}/v1",
        voice_id: "${KOKORO_VOICE_ID:-zm_yunxi}",
        model_id: "${KOKORO_MODEL_ID:-kokoro}",
        output_format: "wav",
        rate: 24000,
      },
    },
],

    第一阶段：配置解析（parse_lifecycle_hooks）¶

    发生在 load_mode_config() 的第 7 步，位于 hook.py:568：

    def parse_lifecycle_hooks(raw_hooks: List[Dict], api_key=None) -> List[LifecycleHook]:
    hooks = []
    for hook_data in raw_hooks:
        handler_config = hook_data.get("handler_config", {}).copy()

        # 如果 handler_config 里没有 api_key，注入全局的
        if api_key is not None and "api_key" not in handler_config:
            handler_config["api_key"] = api_key

        hook = LifecycleHook(
            hook_type=LifecycleHookType(hook_data["hook_type"]),   # "on_startup" → ON_STARTUP
            handler_type=hook_data["handler_type"],                # "message"
            handler_config=handler_config,                         # {message, tts_provider, voice_id, ...}
            async_execution=hook_data.get("async_execution", True),
            timeout_seconds=hook_data.get("timeout_seconds", 5.0),
            on_failure=hook_data.get("on_failure", "ignore"),
            priority=hook_data.get("priority", 0),
        )
        hooks.append(hook)
    return hooks

    结果：配置中的 JSON5 对象 → LifecycleHook dataclass 实例列表，存储在 ModeConfig.lifecycle_hooks 中。

    LifecycleHook dataclass¶

    @dataclass
class LifecycleHook:
    hook_type: LifecycleHookType          # 哪种生命周期事件
    handler_type: str                     # "message" | "command" | "function" | "action"
    handler_config: Dict[str, Any]        # handler 的配置参数
    async_execution: bool = True          # 是否异步执行
    timeout_seconds: Optional[float] = 5.0  # 超时时间
    on_failure: str = "ignore"            # 失败策略: "ignore" | "abort"
    priority: int = 0                     # 优先级 (高的先执行)

    二、五种生命周期事件¶

    class LifecycleHookType(Enum):
    ON_ENTRY = "on_entry"         # 进入 mode 时
    ON_EXIT = "on_exit"           # 离开 mode 时
    ON_STARTUP = "on_startup"     # 系统启动时（全局钩子）或 mode 首次加载时
    ON_SHUTDOWN = "on_shutdown"   # 系统关闭时
    ON_TIMEOUT = "on_timeout"     # mode 超时时

    触发时机全景¶

    系统启动
  ├─ execute_global_lifecycle_hooks(ON_STARTUP)  ← 全局级，所有 mode 共享
  ├─ _initialize_mode("welcome")
  │    └─ load_components(...)
  └─ execute mode lifecycle_hooks(ON_STARTUP)     ← mode 级，只有当前 mode

模式切换 (welcome → conversation)
  ├─ execute old_mode hooks(ON_EXIT)              ← 旧 mode 退出
  ├─ execute_global_lifecycle_hooks(ON_EXIT)       ← 全局退出
  ├─ [更新 state]
  ├─ execute new_mode hooks(ON_ENTRY)              ← 新 mode 进入
  └─ execute_global_lifecycle_hooks(ON_ENTRY)       ← 全局进入

模式超时
  └─ execute mode hooks(ON_TIMEOUT)               ← 超时钩子

系统关闭
  ├─ execute mode hooks(ON_SHUTDOWN)              ← mode 级
  └─ execute_global_lifecycle_hooks(ON_SHUTDOWN)   ← 全局级

    三、execute_lifecycle_hooks() 核心执行逻辑¶

    位于 hook.py:608：

    async def execute_lifecycle_hooks(
    hooks: List[LifecycleHook],       # 所有已注册的钩子
    hook_type: LifecycleHookType,     # 要执行哪种类型 (如 ON_STARTUP)
    context: Optional[Dict] = None,   # 上下文信息 (mode名、系统名、时间戳等)
) -> bool:
    if context is None:
        context = {}
    context.update({"hook_type": hook_type.value})

    # 1. 过滤出匹配类型的钩子
    relevant_hooks = [hook for hook in hooks if hook.hook_type == hook_type]

    # 2. 按 priority 降序排列 (priority 高的先执行)
    relevant_hooks.sort(key=lambda h: h.priority, reverse=True)

    if not relevant_hooks:
        return True  # 没有匹配的钩子 → 成功

    logging.info(f"Executing {len(relevant_hooks)} {hook_type.value} hooks")

    all_successful = True

    # 3. 逐个执行
    for hook in relevant_hooks:
        try:
            # 3a. 根据 handler_type 创建对应的 handler
            handler = create_hook_handler(hook)

            if handler:
                # 3b. 执行 (支持超时)
                if hook.async_execution:
                    if hook.timeout_seconds:
                        success = await asyncio.wait_for(
                            handler.execute(context),
                            timeout=hook.timeout_seconds
                        )
                    else:
                        success = await handler.execute(context)
                else:
                    success = await handler.execute(context)

                # 3c. 失败处理
                if not success:
                    all_successful = False
                    if hook.on_failure == "abort":   # abort → 立即终止所有后续钩子
                        return False
                    if hook.on_failure == "ignore":   # ignore → 记录但继续下一个
                        pass

        except asyncio.TimeoutError:
            # 超时 → 失败 + 可能的 abort
            all_successful = False
            if hook.on_failure == "abort":
                return False
        except Exception as e:
            all_successful = False
            if hook.on_failure == "abort":
                return False

    return all_successful

    失败策略对比¶

    on_failure 行为
    "ignore" (默认) 记录错误日志，继续执行后续钩子
    "abort" 立即返回 False，终止所有后续钩子

    四、四种 Handler 类型¶

    create_hook_handler() 根据 handler_type 创建对应的 handler：

    def create_hook_handler(hook: LifecycleHook) -> Optional[LifecycleHookHandler]:
    handler_type = hook.handler_type.lower()

    if handler_type == "message":
        config = MessageHookConfig(**hook.handler_config)
        return MessageHookHandler(config)
    elif handler_type == "command":
        config = CommandHookConfig(**hook.handler_config)
        return CommandHookHandler(config)
    elif handler_type == "function":
        config = FunctionHookConfig(**hook.handler_config)
        return FunctionHookHandler(config)
    elif handler_type == "action":
        config = ActionHookConfig(**hook.handler_config)
        return ActionHookHandler(config)

    1. message — 播放 TTS 语音¶

    最常用的类型。支持三种 TTS 引擎：Kokoro、ElevenLabs、Riva。

    class MessageHookHandler(LifecycleHookHandler):
    async def execute(self, context):
        # 1. 支持 {变量} 格式化 (如 "Hello {mode_name}")
        formatted_message = self.config.message.format(**context)

        logging.info(f"Lifecycle hook message: {formatted_message}")

        # 2. 创建 TTS Provider
        provider = self._create_tts_provider()
        #    provider_type="kokoro" → KokoroTTSProvider(url, voice_id="zm_yunxi", ...)
        #    provider_type="elevenlabs" → ElevenLabsTTSProvider(...)
        #    provider_type="riva" → RivaTTSProvider(...)

        # 3. 启动 Provider + 将消息加入播放队列
        provider.start()
        provider.add_pending_message(formatted_message)

        return True

    配置示例（你的 welcome 配置）： 

    {
    hook_type: "on_startup",
    handler_type: "message",
    handler_config: {
        message: "你好，我是 Koala。你可以告诉我你的名字...",
        tts_provider: "kokoro",
        base_url: "http://127.0.0.1:8880/v1",
        voice_id: "zm_yunxi",

    2. command — 执行 Shell 命令¶

    class CommandHookHandler(LifecycleHookHandler):
    async def execute(self, context):
        # 1. 格式化命令字符串
        formatted_command = self.config.command.format(**context)

        # 2. 创建子进程执行
        process = await asyncio.create_subprocess_shell(
            formatted_command,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )

        stdout, stderr = await process.communicate()

        # 3. 检查返回值
        if process.returncode == 0:
            logging.info(f"Hook command output: {stdout.decode().strip()}")
            return True
        else:
            logging.error(f"Hook command failed: {stderr.decode().strip()}")
            return False

    配置示例： 

    {
    hook_type: "on_startup",
    handler_type: "command",
    handler_config: {
        command: "python scripts/init_audio.py --device {alsa_card}"
    }
}

    3. function — 调用 Python 函数¶

    从 src/hooks/<module_name>.py 动态加载并调用指定函数。

    class FunctionHookHandler(LifecycleHookHandler):
    async def execute(self, context):
        # 1. 从 src/hooks/<module_name>.py 动态加载函数
        func = self._find_function_in_module(
            self.config.module_name,    # 如 "greeting_hook"
            self.config.function         # 如 "on_greeting_start"
        )

        # 2. 合并配置字典和上下文
        merged_context = {**self.config.model_dump(), **context}

        # 3. 调用 (支持 async 和 sync 函数)
        if asyncio.iscoroutinefunction(func):
            result = await func(merged_context)
        else:
            result = func(merged_context)

        return result is not False

    _find_function_in_module() 的查找逻辑： 1. 定位 src/hooks/<module_name>.py 2. 用正则验证函数定义存在（^(?:async\s+)?def\s+<function_name>\s*\(） 3. importlib.import_module(f"hooks.{module_name}") 动态导入 4. getattr(module, function_name) 获取函数引用

    配置示例： 

    {
    hook_type: "on_entry",
    handler_type: "function",
    handler_config: {
        module_name: "greeting_hook",     // → src/hooks/greeting_hook.py
        function: "on_greeting_start",    // → 模块中的 on_greeting_start()
    }
}

    4. action — 执行 Agent Action¶

    动态加载一个完整的 Action 并执行。

    class ActionHookHandler(LifecycleHookHandler):
    async def execute(self, context):
        # 1. 动态加载一个 Action（和 agent_actions 中同样的加载机制）
        self.action = load_action({
            "type": self.config.action_type,     # 如 "speak"
            "config": self.config.action_config,  # Action 参数
        })

        # 2. 连接并执行
        await self.action.connector.connect(context.get("input_data"))
        return True

    五、从 cortex.py 看两层钩子的调用¶

    # runtime/cortex.py → ModeCortexRuntime.run()

async def run(self):
    # ══════ 第一层：全局钩子 (Global) ══════
    # 由 ModeSystemConfig.execute_global_lifecycle_hooks() 执行
    # 钩子来源：配置顶层的 global_lifecycle_hooks (welcome 配置中没有定义)
    startup_context = {
        "system_name": self.mode_config.name,           # "welcome"
        "initial_mode": self.mode_manager.current_mode_name,  # "welcome"
        "timestamp": asyncio.get_event_loop().time(),   # 当前时间戳
    }
    startup_success = await self.mode_config.execute_global_lifecycle_hooks(
        LifecycleHookType.ON_STARTUP,   # 只执行 hook_type=="on_startup" 的钩子
        startup_context                 # 传入上下文
    )
    # → ModeSystemConfig.execute_global_lifecycle_hooks()
    #   → execute_lifecycle_hooks(self.global_lifecycle_hooks, ON_STARTUP, context)

    # ... 初始化 mode (load_components, 创建 Fuser, Orchestrator...) ...

    # ══════ 第二层：当前 mode 的钩子 (Mode-level) ══════
    initial_mode_config = self.mode_config.modes[self.mode_manager.current_mode_name]
    await initial_mode_config.execute_lifecycle_hooks(
        LifecycleHookType.ON_STARTUP,   # Mode 级别的 on_startup
        startup_context
    )
    # → ModeConfig.execute_lifecycle_hooks()
    #   → 先注入 mode 元信息到 context
    #   → 再调 execute_lifecycle_hooks(self.lifecycle_hooks, ON_STARTUP, context)
    #     ← 你的 "你好，我是 Koala..." TTS 就在这里被执行！

    ModeConfig.execute_lifecycle_hooks() 的包装¶

    位于 config.py:422，在调用 hook.py 之前注入 mode 元信息：

    # ModeConfig.execute_lifecycle_hooks()
async def execute_lifecycle_hooks(self, hook_type, context=None):
    if context is None:
        context = {}

    # 注入 mode 元信息 → 可以在 message 中用 {mode_name} 等变量
    context.update({
        "mode_name": self.name,
        "mode_display_name": self.display_name,
        "mode_description": self.description,
    })

    return await execute_lifecycle_hooks(self.lifecycle_hooks, hook_type, context)

    六、完整执行时序（welcome 配置）¶

    cortex.py: run()
  │
  ├─ startup_context = {system_name: "welcome",
  │                      initial_mode: "welcome",
  │                      timestamp: 1728000000.0}
  │
  ├─ mode_config.execute_global_lifecycle_hooks(ON_STARTUP, startup_context)

  │    └─ load_components(...)

  │    │
  │    ├─ context 注入 mode 元信息:
  │    │    {**startup_context,
  │    │     mode_name: "welcome",

  │    │

  │    │           voice_id: "zm_yunxi",
  │    │           model_id: "kokoro",
  │    │       }
  │    │   )]
  │    │
  │    ├─ create_hook_handler(hook) → MessageHookHandler(config)
  │    │
  │    └─ await handler.execute(context)
  │         ├─ formatted_message = "你好，我是 Koala。你可以告诉我你的名字..."
  │         ├─ provider = KokoroTTSProvider(
  │         │       url="http://127.0.0.1:8880/v1",

  │         │       model_id="kokoro"
  │         │   )
  │         ├─ provider.start()     # 初始化 HTTP 客户端 + 消息队列

  │         │    └─ 消息入队 → 后台线程 → HTTP POST → Kokoro TTS 服务
  │         │       → 音频合成 → 扬声器播放

  │

    七、总结¶

    配置 JSON5 lifecycle_hooks
      │
      ▼
parse_lifecycle_hooks(raw_hooks, api_key)
   → List[LifecycleHook]  dataclass 对象
      │
      ▼
execute_lifecycle_hooks(hooks, hook_type, context)
   ├─ 过滤: 只执行 hook_type 匹配的钩子
   ├─ 排序: 按 priority 降序
   ├─ create_hook_handler(hook) → handler_type 匹配工厂
   │    ├─ "message" → MessageHookHandler → TTS 播放
   │    ├─ "command" → CommandHookHandler → Shell 子进程
   │    ├─ "function" → FunctionHookHandler → 动态加载 Python 函数
   │    └─ "action" → ActionHookHandler → 执行 Agent Action
   └─ handler.execute(context)
        └─ on_failure: "ignore" (继续) | "abort" (终止)
