    hook.py 文件详解¶

    文件路径：/home/nvidia/MAGIC/src/runtime/hook.py

    这个文件实现了生命周期钩子系统，允许在系统启动、模式切换、退出等关键时机执行自定义操作（如播放欢迎语音、执行命令、调用函数等）。

    枚举类¶

    LifecycleHookType¶

    定义位置：第 14-26 行

    作用：定义钩子的触发时机。

    class LifecycleHookType(Enum):
    ON_ENTRY = "on_entry"       # 进入模式时执行
    ON_EXIT = "on_exit"         # 退出模式时执行
    ON_STARTUP = "on_startup"   # 系统启动时执行
    ON_SHUTDOWN = "on_shutdown" # 系统关闭时执行
    ON_TIMEOUT = "on_timeout"   # 模式超时时执行

    使用场景：

    钩子类型 触发时机 典型用途
    ON_STARTUP 系统首次启动 播放欢迎语、初始化硬件
    ON_ENTRY 进入某个模式 模式切换提示、加载资源
    ON_EXIT 退出某个模式 清理资源、保存状态
    ON_SHUTDOWN 系统关闭 播放结束语、保存数据
    ON_TIMEOUT 模式超时 超时提醒、自动切换

    数据类¶

    LifecycleHook¶

    定义位置：第 29-54 行

    作用：定义单个钩子的完整配置。

    @dataclass
class LifecycleHook:
    hook_type: LifecycleHookType        # 钩子类型
    handler_type: str                   # 处理器类型
    handler_config: Dict[str, Any]      # 处理器配置
    async_execution: bool = True        # 是否异步执行
    timeout_seconds: Optional[float] = 5.0  # 超时时间
    on_failure: str = "ignore"          # 失败策略
    priority: int = 0                   # 优先级（越高越先执行）

    字段说明：

    字段 类型 说明
    hook_type LifecycleHookType 钩子触发时机
    handler_type str 处理器类型：message, command, function, action
    handler_config Dict 传递给处理器的配置
    async_execution bool 是否异步执行（默认 True）
    timeout_seconds float 执行超时时间（默认 5.0 秒）
    on_failure str 失败策略：ignore 或 abort
    priority int 优先级（越高越先执行）

    FunctionHookHandler¶

    定义位置：第 318-398 行

    作用：调用 Python 函数（从 hooks/ 目录）。

    执行流程：

    execute(context)
    │
    ▼
_find_function_in_module(module_name, function_name)
    │
    ▼
查找模块文件：/home/nvidia/MAGIC/src/hooks/{module_name}.py
    │
    ▼
导入模块：importlib.import_module(f"hooks.{module_name}")
    │
    ▼
获取函数：getattr(module, function_name)
    │
    ▼
判断是否异步函数
    ├── async → await func(context)
    └── sync → func(context)
    │
    ▼
return result is not False

    函数签名要求：

# 同步函数
def start_native_relocation_hook(context: Dict[str, Any]) -> bool:
    unitree_ethernet = context.get("unitree_ethernet")
    # ...
    return True

# 异步函数
async def async_hook(context: Dict[str, Any]) -> bool:
    await some_async_operation()
    return True

    parse_lifecycle_hooks¶

    定义位置：第 472-503 行

    作用：将原始配置解析为 LifecycleHook 对象列表。

    参数： - raw_hooks: List[Dict] - 原始钩子配置列表 - api_key: Optional[str] - 全局 API 密钥（自动注入）

    返回值： - List[LifecycleHook] - 解析后的钩子对象列表

    流程：

    parse_lifecycle_hooks(raw_hooks, api_key)
    │
    ▼
遍历 raw_hooks
    │
    ▼
对每个钩子：
    ├── 复制 handler_config
    ├── 注入全局 api_key（如果未指定）
    └── 创建 LifecycleHook 对象
    │
    ▼
return List[LifecycleHook]

    execute_lifecycle_hooks¶

    定义位置：第 506-560 行

    作用：执行指定类型的所有钩子（核心入口函数）。

    参数： - hooks: List[LifecycleHook] - 钩子列表 - hook_type: LifecycleHookType - 要执行的钩子类型 - context: Optional[Dict[str, Any]] - 上下文信息

    返回值： - bool - 所有钩子是否都执行成功

    执行流程：

    execute_lifecycle_hooks(hooks, hook_type, context)
        │
        ▼
    过滤相关钩子：hook.hook_type == hook_type
        │
        ▼
    按优先级排序（priority 降序）
        │
        ▼
    遍历每个钩子
        │
        ▼
    create_hook_handler(hook)
        │
        ▼
    执行 handler.execute(context)
        │
        ├── async_execution → 异步执行
        ├── timeout_seconds → 设置超时
        └── sync → 同步执行
        │
        ▼
    检查执行结果
        │
        ├── success → 继续
        └── failure + on_failure == "abort" → 立即返回 False
        │
        ▼
    return all_successful

    完整使用示例¶

    配置文件示例：¶

    lifecycle_hooks: [
    // 启动时播放欢迎语
    {
        hook_type: "on_startup",
        handler_type: "message",
        handler_config: {
            message: "你好，我是考拉一号。",
            tts_provider: "qwen",
            api_key: "${DASHSCOPE_API_KEY}",
            voice_id: "Cherry",
            model_id: "qwen3-tts-flash",
        },
        priority: 1,
    },

    // 启动时调用自定义函数
    {
        hook_type: "on_startup",
        handler_type: "function",
        handler_config: {
            module_name: "native_relocation_hook",
            function: "start_native_relocation_hook",
            unitree_ethernet: "${UNITREE_ETHERNET}",
            map_pcd: "/home/unitree/maps/kitchen_pro.pcd",
        },
        timeout_seconds: 45,
        priority: 2,  // 先执行这个
    },

    // 退出时执行命令
    {
        hook_type: "on_exit",
        handler_type: "command",
        handler_config: {
            command: "echo 'Mode {mode_name} exited'"
        },
    },
]

    执行流程：¶

    系统启动
    │
    ▼
execute_lifecycle_hooks(hooks, LifecycleHookType.ON_STARTUP, context)
    │
    ▼
找到 2 个 on_startup 钩子
    │
    ▼
按优先级排序：priority=2 > priority=1
    │
    ▼
执行 priority=2 的函数钩子
    → start_native_relocation_hook(context)
    → 启动机器人定位服务
    │
    ▼
执行 priority=1 的消息钩子
    → TTS 播放 "你好，我是考拉一号。"
    │
    ▼
return True

    类与函数关系图¶

    配置解析：
    raw_hooks (JSON)
        ↓
    parse_lifecycle_hooks()
        ↓
    List[LifecycleHook]
        ↓
    create_hook_handler()
        ↓
    LifecycleHookHandler

执行流程：
    execute_lifecycle_hooks()
        ↓
    过滤 + 排序
        ↓
    for each hook:
        ↓
    create_hook_handler()
        ↓
    ├── MessageHookHandler.execute() → TTS 播报
    ├── CommandHookHandler.execute() → 执行命令
    ├── FunctionHookHandler.execute() → 调用函数
    └── ActionHookHandler.execute() → 执行动作

    设计要点¶

    要点 说明
    异步执行 默认异步执行，支持超时控制
    优先级 同类型钩子按优先级顺序执行（越高越先）
    失败策略 ignore 继续执行，abort 立即停止
    上下文传递 支持变量格式化 {variable}
    多种处理器 支持 TTS、命令、函数、动作四种类型
    自动注入 自动注入全局 API 密钥到配置中
    延迟导入 函数钩子使用延迟导入，避免循环依赖

    在 config.py 中的使用¶

    from runtime.hook import (
    LifecycleHook,
    LifecycleHookType,
    parse_lifecycle_hooks,
    execute_lifecycle_hooks,
)

# 解析全局钩子
global_lifecycle_hooks = parse_lifecycle_hooks(
    raw_config.get("global_lifecycle_hooks", []),
    api_key=g_api_key
)

# 解析模式钩子
mode_config.lifecycle_hooks = parse_lifecycle_hooks(
    mode_data.get("lifecycle_hooks", []),
    api_key=g_api_key
)

# 执行钩子
await mode_system_config.execute_global_lifecycle_hooks(
    LifecycleHookType.ON_STARTUP
)

    实际例子：Koala Fetch 的完整 Hook 链¶

    以 autonomy_mid360 导航配置为例，展示一次完整的取物任务中各 Hook 的执行时序：

    系统启动
    │
    ├── on_startup: start_autonomy_mid360_nav_hook()
    │     ├── 检查 tmux 是否安装
    │     ├── 检查 Docker 容器是否运行
    │     ├── 停止旧的 FAST-LIO + nav session（如果有）
    │     ├── 启动 Livox 适配器 session（可选）
    │     ├── 启动 FAST-LIO session (tmux new-session)
    │     │     └── 自动发送 's' 键启动建图
    │     ├── 启动导航 session (FAR Planner + local planner)
    │     ├── 等待所有 ROS 2 topic 就绪（15 个 required_topics）
    │     ├── 加载先验 V-Graph
    │     ├── 等待 V-Graph 连通性检查通过
    │     └── 发布导航边界
    │
    ├── on_entry (nav 模式):
    │     ├── go2_stand_up_hook()     # 站立
    │     ├── 重定位
    │     ├── 开始导航到仓库
    │     └── 播报 "我走啦"
    │
    │  ... 导航中 (LLM tick) ...
    │
    ├── on_exit (nav → grasp):
    │     ├── stop_fetch_nav_on_exit() # 停止导航
    │     └── go2_stand_down_hook()    # 趴下
    │
    │  ... 抓取中 ...
    │
    └── on_shutdown:
          ├── stop_autonomy_mid360_nav_hook()
          │     ├── 发送 C-c 到 nav session
          │     ├── 发送 C-c 到 FAST-LIO session
          │     ├── 发送 StopMove 到机器人
          │     └── (可选) 停止 Docker 容器
          └── 停止 Mid360 驱动

    Hook vs Action vs Background¶

    Hook Action (LLM输出) Background
    触发者 模式切换事件 LLM 决策 系统启动
    执行时机 进入/退出模式瞬间 每个 tick 持续运行
    确定性 预配置，100% 确定 LLM 决定，非确定 预配置
    用途 硬件管线的启停编排 任务执行的具体动作 传感器数据持续采集
    例子 "进入 nav 前先站起来" "导航到仓库" "每 0.1s 读一次里程计"
