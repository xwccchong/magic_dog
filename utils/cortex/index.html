    Cortex — 系统总调度器 (src/runtime/cortex.py)¶

    文件路径：src/runtime/cortex.py（~1828 行）

    唯一核心类 ModeCortexRuntime。把所有组件串成一个运行中的系统——初始化一切，每个 tick 调度数据流和决策链，优雅地启停组件。机器人的中枢神经系统。

    整体架构¶

    ModeCortexRuntime.run()
    │
    ├── ① 执行全局 ON_STARTUP hooks（一次性）
    ├── ② _initialize_mode(default_mode) → 加载配置/创建各组件的 Orchestrator
    ├── ③ 执行模式 ON_STARTUP hooks（一次性）
    ├── ④ _start_orchestrators() → 启动并行任务:
    │
    └── await asyncio.gather(
          ├── _run_cortex_loop()           ← ★ 核心 tick 循环
          ├── _handle_mode_transitions()   ← 模式切换处理器
          ├── input_orchestrator.listen()  ← Input 数据采集
          ├── config_watcher_task          ← 热重载监视
          └── ...其他 orchestrator tasks
        )

    成员变量一览¶

    class ModeCortexRuntime:
    # 核心依赖
    mode_config: ModeSystemConfig        # 完整的模式系统配置
    mode_manager: ModeManager            # 模式切换管理器
    io_provider: IOProvider              # 全局状态黑板
    sleep_ticker_provider: SleepTickerProvider  # 睡眠/tick 控制

    # 运行时组件（每个模式不同）
    current_config: RuntimeConfig         # 当前模式的配置
    fuser: Fuser                         # 提示词融合器
    action_orchestrator: ActionOrchestrator    # 动作派发器
    input_orchestrator: InputOrchestrator      # 输入采集器
    background_orchestrator: BackgroundOrchestrator  # 后台任务管理器
    simulator_orchestrator: SimulatorOrchestrator    # 仿真器
    mcp_orchestrator: MCPOrchestrator           # MCP 工具管理器
    long_term_memory: LongTermMemory            # 长期记忆

    # Async tasks
    cortex_loop_task: asyncio.Task       # 核心 tick 循环
    input_listener_task: asyncio.Task    # 输入监听
    action_task: asyncio.Future          # 动作执行
    background_task: asyncio.Future      # 后台任务
    simulator_task: asyncio.Future       # 仿真
    mode_transition_task: asyncio.Task   # 模式切换
    config_watcher_task: asyncio.Task    # 热重载

    # 生命周期控制
    _cortex_loop_generation: int         # 用于取消旧 tick 的"代际"编号
    _is_reloading: bool                  # 是否正在重载
    _mode_initialized: bool              # 模式是否已初始化

    函数分类速查¶

    一、生命周期管理¶

    函数 行 作用
    run() 693 ★ 总入口：全局 hook → 初始化 → 启动 orchestrator → asyncio.gather 所有任务 → 关闭 hook → 清理
    _initialize_mode(name) 335 加载模式配置、执行硬件预检、创建 Fuser/ActionOrchestrator/Background/Simulator/MCP
    _start_orchestrators() 621 创建 InputOrchestrator → 启动 MCP → 创建 cortex_loop_task 和 mode_transition_task
    _stop_current_orchestrators() 460 递增 generation（使旧 loop 失效）→ 停止所有 orchestrator → 取消所有 async task → 关闭 HTTP clients
    _cleanup_tasks() 656 最终清理：取消所有 task、停止 ConfigProvider
    _close_current_mode_http_clients() 559 关闭当前模式的 cortex_llm + voice_planner_llm + Input HTTP 客户端
    _close_global_http_clients() 586 关闭全局的 mode_router_llm + voice_task_planner_llm

    二、主循环 (_run_cortex_loop → _tick)¶

    函数 行 作用
    _run_cortex_loop() 789 while True: → await sleep(1/hertz) → await _tick()
    _tick(cortex_generation) 819 ★ 单个 tick 的全部逻辑

    _tick() 每一轮的完整流程：

    _tick(cortex_generation)
    │
    ├── increment_tick()                        # tick 计数 +1
    ├── _remember_fresh_voice_input()           # 新 Voice → 长期记忆
    │
    ├── fuser.fuse(inputs, promises)            # ① 融合所有传感器→完整 prompt
    │
    ├── _run_voice_task_planner_if_configured() # ② 阶段 1: 全局 planner 分解语音→子任务
    ├── _advance_voice_task_from_status()       # ③ 根据硬件状态推进子任务指针
    ├── active_subtask = planned or current     # ④ 确定当前子任务
    │
    ├── 各种跳过条件检查:
    │   ├── grasp 已完成 → 等切换
    │   ├── nav/grasp subtask 正在执行中 → 等硬件
    │   └── action_gate 要求新鲜 Voice 但没有 → 不调 LLM
    │
    ├── _prepare_active_voice_task_for_current_mode() # ⑤ 将子任务注入 IOProvider 的 Voice
    ├── replace_voice_input_in_prompt()               # ⑥ 用子任务文本替换 prompt 中的 Voice
    │
    └── _execute_cortex_prompt(prompt, gen)           # ⑦ 阶段 2: 调 LLM → 执行动作

    _tick() 的三种退出路径：

    路径 条件 结果
    跳过 LLM 没有新鲜 Voice（action_gate 未满足）、nav/grasp 正在执行中、grasp 已完成等切换 return，本轮不调 LLM
    走 Planner 有 fresh Voice 且 voice_planner_llm 已配置 planner 分解为 sub_voices → 逐个调 LLM
    默认 无 planner 或 planner 未触发 直接用 fused prompt 调 LLM

    三、两阶段 LLM 调度¶

    函数 行 作用
    _run_voice_task_planner_if_configured(input_text) 937 阶段 1（全局）：调用 voice_task_planner_llm 将语音分解为子任务列表，写入 voice_task_context
    _run_voice_planner_if_configured(prompt, gen) 1490 阶段 1（模式级）：调用当前 mode 的 voice_planner_llm，逐个执行 sub_voices
    _execute_cortex_prompt(prompt, gen) 1537 阶段 2：调用 cortex_llm.ask_stream() → MCP tool-calling loop → repair → simulator → action_orchestrator.promise()

    两种 Planner 的区别：

    _tick()
    │
    ├── _run_voice_task_planner_if_configured(last_input)  ← 全局 planner（跨模式多步规划）
    │     用 voice_task_planner_llm 分解 Voice → sub_voices → 存入 voice_task_context
    │     输出: [导航到仓库, 抓取饮料, 导航到前台, 递给用户]
    │
    └── _run_voice_planner_if_configured(prompt, gen)      ← 模式级 planner（模式内分解）
          用当前 mode 的 voice_planner_llm → 逐个调 _execute_cortex_prompt()
    voice_task_planner_llm (全局) voice_planner_llm (模式级)
    配置位置 mode_config 顶层 每个 mode 各自配置
    触发 有新 Voice 时，一次性 每个 tick 检查
    输入 纯语音文本 + 长期记忆 Fuser 融合后的完整 prompt
    输出 sub_voices + task_plan (含 mode 路由) sub_voices
    子任务存储 写入 voice_task_context，由 _tick 每轮取当前步骤 立即逐个调 LLM 执行

    四、LLM 输出后处理¶

    函数 行 作用
    repair_speak_only_voice_intents(prompt, actions) 97 ★ 安全网：LLM 只输出 speak 但 Voice 明显是"向左看"/"打招呼"/"复位"时，用正则自动追加 motion action
    replace_voice_input_in_prompt(prompt, voice) 153 用子任务文本替换 prompt 中的 Voice 段
    _mark_voice_task_started_for_action_dispatch(actions) 1272 LLM 输出 nav/grasp 动作后，标记当前子任务步骤为 started
    _has_fresh_required_input_for_llm() 1676 Action Gate 入口检查：当前 tick 是否有新鲜 Voice？

    repair_speak_only_voice_intents 规则表：

    Voice 匹配 追加的动作
    回到原位 / 复位 / 回 初始 arm_x5_reset
    打招呼 / 问好 / 挥手 hello
    向左看 / 向左转 arm_x5_joint_nudge(direction="left")
    向右看 / 向右转 arm_x5_joint_nudge(direction="right")
    不要...复位/打招呼/向左/向右 不追加（负向匹配拦截）

    技能调用方式总结¶

    Cortex 通过四种方式触发不同技能/组件：

    方式 触发时机 调用的技能 例子
    Lifecycle Hooks 模式切换时（on_startup / on_entry / on_exit / on_shutdown） src/hooks/*.py 中的硬件管线启停函数 进入 nav → go2_stand_up_hook() + start_autonomy_mid360_nav_hook()
    LLM Function Calling 每个 tick 的 _execute_cortex_prompt() agent_actions 中配置的所有 Connector navigate_location("仓库")、grasp_object("bottle")
    Voice Task Planner 有新 Voice 输入时 全局/模式级 planner LLM 分解子任务 "去仓库拿饮料" → [导航到仓库, 抓取饮料, 返回起点]
    MCP Orchestrator LLM 输出 mcp_ 开头的工具调用时 外部 MCP 工具服务器 mcp_weather_get_forecast(city="北京")

    完整 Tick 数据流¶

    Tick N
    │
    ├── tick_counter: N-1 → N
    ├── InputOrchestrator: 后台持续采集，数据写入 IOProvider._inputs
    │
    ├── Fuser.fuse(all_inputs):
    │     收集 formatted_latest_buffer() → 拼 system_prompt + LAWS + INPUTS + ACTIONS
    │
    ├── Voice Task Planner (如有新 Voice):
    │     "去仓库拿饮料送到前台" → [导航到仓库, 抓取饮料, 导航到前台, 递给用户]
    │
    ├── 检查子任务队列 + 硬件状态 → 确定 active_subtask
    │     active_subtask = "导航到仓库"
    │
    ├── replace_voice_input_in_prompt():
    │     prompt 中 "Voice: 去仓库拿饮料..." → "Voice: 导航到仓库"
    │
    ├── _execute_cortex_prompt():
    │     cortex_llm.ask_stream(prompt)
    │       → [navigate_location("仓库")]
    │     ├── MCP tools? → mcp_orchestrator 多轮 tool-calling loop
    │     ├── repair_speak_only_voice_intents()
    │     ├── simulator.promise(actions)
    │     └── action_orchestrator.promise(actions)
    │           └── 遍历 actions → normalize → action_gate 检查
    │               → _get_agent_action (llm_label 匹配)
    │               → _promise_action (解析 value → 类型转换 → connector.connect)
    │
    ├── Action 执行:
    │     navigate_location → publish_goal.sh → ROS 2 /goal_point → FAR Planner → Go2 移动
    │     speak → Qwen TTS API → 机器人播报语音
    │
    └── 硬件状态反馈 → _advance_voice_task_from_status()
          → 导航到达 → 子任务完成 → 推进到下一步

Tick N+1: 当前子任务 = "抓取饮料" → LLM → grasp_object → ...
Tick N+2: 全部完成 → task_completed → 切换回 welcome
