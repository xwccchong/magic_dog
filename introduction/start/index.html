    start_magic_mini_humble.sh 脚本详解¶

    scripts/start_magic_mini_humble.sh 是 MAGIC MINI 在 Ubuntu 22.04 + ROS 2 Humble 上的一体化启动/停止管理脚本，负责编排 Mid360 激光雷达驱动、导航 Docker 容器和 MAGIC Agent 三层运行时的生命周期。

    一、整体架构¶

    脚本将启动分为两层解耦：

    start        → 底层基础设施（Mid360 驱动 + 导航容器）
start-agent  → 上层 MAGIC Agent（LLM/语音/视觉）

    默认 MAGIC_START_AGENT=false，即 start 只拉起基础设施，不启动 Agent。这样设计是为了让用户可以先稳住导航层，再按需挂载 Agent。

    二、子命令一览¶

    命令 作用
    start 启动 Mid360 驱动 + 导航 Docker 容器（默认不带 Agent）
    start-agent 在 tmux 中启动 MAGIC Agent（src/run.py）
    stop 优雅停止：先 SIGINT Agent → 停容器 → 停驱动
    restart stop + start
    status 显示所有组件运行状态
    attach 进入 Agent 的 tmux 会话
    check 只做前置检查（不启动任何东西）

    三、环境加载 load_env()¶

    从 .env 文件加载所有环境变量，关键变量分类：

    网络与 DDS¶

    变量 默认值 说明
    UNITREE_ETHERNET eno1 Go2 机器狗通信网卡
    CYCLONEDDS_INTERFACE eno1 CycloneDDS 使用的网卡（与 Go2 eth 相同）
    ROS_DOMAIN_ID 0 ROS 域隔离
    MID360_DRIVER_INTERFACE enx00e04c680d5f Mid360 雷达专用 USB 网卡
    MID360_DRIVER_HOST_IP 192.168.200.1 宿主机在雷达子网的静态 IP
    MID360_LIDAR_IP 192.168.200.20 Mid360 雷达 IP

    导航容器¶

    变量 默认值
    MID360_IMAGE magic-mini-mid360-nav:humble
    MID360_CONTAINER magic_mini_mid360_nav
    MID360_MAPS_DIR ${MAGIC_DIR}/service/unitree_native_slam

    Config¶

    变量 默认值
    KOALA_FETCH_CONFIG unitree_go2_koala_nav_vision_no_arm

    Python 路径隔离¶

    • REALSENSE_PYTHONPATH 指向 librealsense 2.57.7 的 Python binding（Python 3.12）
    • 脚本在运行 Agent 时会 取消 ROS Python 路径，因为 ROS 2 Humble 使用 Python 3.10，而 MAGIC 使用 uv 的 Python 3.12，两者必须隔离

    四、CycloneDDS 配置生成 write_cyclonedds_config()¶

    动态生成 .runtime/cyclonedds-<interface>.xml，绑定指定网卡做 DDS 发现：

    <CycloneDDS>
  <Domain Id="any">
    <General>
      <Interfaces>
        <NetworkInterface name="${CYCLONEDDS_INTERFACE}" priority="default" multicast="default" />
      </Interfaces>
      <AllowMulticast>true</AllowMulticast>
    </General>
    <Discovery>
      <ParticipantIndex>auto</ParticipantIndex>
      <MaxAutoParticipantIndex>120</MaxAutoParticipantIndex>
    </Discovery>
  </Domain>
</CycloneDDS>

    这是 Go2 机器人与宿主机之间通过以太网做 ROS 通信的 DDS 通道。

    五、前置检查 check_prerequisites()¶

    分两层检查：

    基础层 (require_agent=false)¶

    • tmux 已安装
    • ROS 2 Humble 存在 (/opt/ros/humble/setup.bash)
    • PCD 地图文件存在 (aaa-fuck-magic-company_20260630_100336.pcd)
    • prior graph 文件存在 (my_prior_graph_final.vgh)
    • Go2 网卡 eno1 在线
    • CycloneDDS 库存在 (libddsc.so)
    • Mid360 网卡配置了静态 IP 192.168.200.1 且雷达 192.168.200.20 可 ping 通
    • Mid360 驱动脚本和 setup.bash 存在

    Agent 层 (require_agent=true)¶

    额外检查：

    • uv 已安装
    • .venv 存在
    • 配置 JSON5 文件存在
    • DASHSCOPE_API_KEY 有值
    • 外部 pyrealsense2 可用（可选，缺失仅警告）

    六、Mid360 驱动管理¶

    start_mid360_driver()¶

    1. 先检查是否已有 driver tmux 会话存活 → 如果有且数据正常，复用
    2. 如果没有 → 创建新 tmux 会话运行 /home/nvidia/ws_mid360/scripts/start_mid360s.sh
    3. 等待 /livox/lidar (PointCloud2) 和 /livox/imu (Imu) 两个 topic 有数据输出
    4. 超时时间内没有数据 → 打印最近 40 行日志并失败退出

    Topic 数据验证使用 ros2 topic echo --once 在临时子 shell 中执行，确保 ROS 2 环境正确且 DDS 通信正常。

    stop_mid360_driver()¶

    杀掉 MID360_DRIVER_SESSION tmux 会话（可通过 MID360_STOP_DRIVER_WITH_STACK 控制）。

    七、导航容器管理¶

    ensure_navigation_runtime()¶

    • Docker 模式：调用 run_container.sh 确保容器 magic_mini_mid360_nav 运行，挂载 maps 目录和 CycloneDDS 配置
    • Host 模式：检查 workspace 的 install/setup.bash 存在

    cleanup_navigation_runtime()¶

    停止顺序严格：

    1. 先停 Docker 容器（防止 lifecycle hook 重新创建 tmux 会话）
    2. 再清理三个 agent 内部的 tmux 会话：
    3. go2_livox_compat
    4. go2_fastlio_autonomy
    5. go2_mid360_autonomy_nav
    6. 每个会话先发 Ctrl+C（grace 2s），再 force kill

    八、MAGIC Agent 运行 run_runtime()¶

    这是 tmux 内部实际执行的函数：

    1. 加载环境、生成 DDS 配置
    2. 清除 ROS 环境变量 — 关键：防止 ROS 2 Python 3.10 与 uv Python 3.12 冲突 
      unset AMENT_PREFIX_PATH CMAKE_PREFIX_PATH COLCON_PREFIX_PATH
unset ROS_DISTRO ROS_VERSION ROS_PYTHON_VERSION PYTHONHOME
    3. 设置 PYTHONPATH 指向 librealsense Python binding
    4. 设置 LD_LIBRARY_PATH 指向 CycloneDDS 库
    5. 关闭 HTTP 代理（机器人本地通信不走代理）
    6. 执行： 
      uv run --no-sync --extra dds --extra wake-word src/run.py unitree_go2_koala_nav_vision_no_arm
      即用 uv 运行 MAGIC 主程序，加载对应的 JSON5 配置

    九、停止流程 stop_stack()¶

    停止顺序严格：

    1. 对 Agent tmux 发 Ctrl+C（触发 on_shutdown 生命周期钩子 → 停导航会话 → 停容器）
    2. 最多等待 2 × MID360_SHUTDOWN_TIMEOUT_SECONDS（默认 90s）
    3. 超时则强制 tmux kill-session
    4. 执行 cleanup_navigation_runtime + stop_mid360_driver

    十、整体启动时序¶

    start (基础层):
  check_prerequisites
  → cleanup_navigation_runtime (如果 MID360_RESET_NAVIGATION_ON_START=true)
  → start_mid360_driver
      → 创建 tmux 会话 magic_mid360_driver
      → 等待 /livox/lidar + /livox/imu 数据 OK
  → ensure_navigation_runtime
      → docker run magic-mini-mid360-nav:humble
  → 完成（基础设施就绪）

start-agent (Agent 层):
  check_prerequisites(require_agent=true)
  → 确认 Docker 容器在跑
  → tmux new-session -s magic_mini_humble
  → 执行 run_runtime:
      → uv run src/run.py
      → 配置中的 lifecycle hooks 触发:
          1. go2_stand_up_hook       → 机器人站起来 (priority 3)
          2. start_autonomy_mid360_nav_hook → 容器内启动 FAST-LIO + 导航 (priority 2)
      → Agent 进入主循环 (2Hz LLM 推理 + 输入采集)

    十一、Python 环境隔离详情¶

    MAGIC 运行时的 Python 环境与 ROS 2 完全解耦：

    ┌─────────────────────────────────┐  ┌─────────────────────────────────┐
│  ROS 2 Humble                   │  │  MAGIC Runtime                  │
│  Python 3.10                    │  │  Python 3.12 (uv .venv)         │
│                                 │  │                                 │
│  /opt/ros/humble/               │  │  .venv/                         │
│  ├─ rclpy                       │  │  ├─ openai                      │
│  ├─ sensor_msgs                 │  │  ├─ sherpa_onnx                 │
│  └─ cyclonedds                  │  │  └─ pyrealsense2 (外部)          │
│                                 │  │                                 │
│  Mid360 driver 使用此环境        │  │  Agent / LLM / ASR 使用此环境     │
└─────────────────────────────────┘  └─────────────────────────────────┘
         │                                      │
         └──────── CycloneDDS 网络 ─────────────┘
              DDS 消息在两者之间传递
              (PointCloud2, Imu, Odometry...)

    总结¶

    核心设计思想是分层解耦 + 优雅启停：

    • 底层（Mid360 驱动 + Docker 容器）先独立就绪，可脱离 Agent 长期运行
    • 上层（MAGIC Agent）按需叠加，崩溃不影响导航层
    • 停止顺序严格：先停 Agent（触发 shutdown hooks），再停容器，最后停驱动
    • Python 环境隔离：ROS 2 Humble 的 Python 3.10 和 MAGIC uv 的 Python 3.12 完全分开，通过 CycloneDDS 以网络通信方式交换数据
    • tmux 管理全部会话：便于 attach 调试、状态查询和统一生命周期管理
