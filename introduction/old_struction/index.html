    MAGIC (OM1) 项目结构详解¶

    一、项目定位¶

    OM1 是 OpenMind 开源的模块化 AI Agent 运行时系统，核心功能是：

    • 将多模态感知输入（语音、视觉、GPS、激光雷达等）融合为结构化 prompt
    • 通过 LLM 推理生成动作指令
    • 将动作分发到不同的机器人硬件执行器
    • 支持运行时多模式(Mode)动态切换（如闲谈模式 ↔ 导航模式 ↔ 抓取模式）

    技术上是一个事件驱动 + LLM 推理的机器人"大脑"中间件，不绑定特定硬件形态。

    三、核心架构：运行时控制流程¶

    整个系统的核心是一个无限 Ticker Loop，以固定频率（默认 1Hz，可配置）运行：

    ┌─────────────────────────────────────────────────────────────────┐
│                     ModeCortexRuntime.run()                       │
│                                                                   │
│  ┌──────────────┐   ┌──────────────┐   ┌───────────────────────┐ │
│  │ InputListener │   │  CortexLoop   │   │ ActionOrchestrator    │ │
│  │ (async task)  │   │  (async task) │   │ (async task)          │ │
│  │               │   │               │   │                       │ │
│  │ 持续接收传感器 │──▶│ 每个 tick:    │──▶│ 并发/顺序执行 Action   │ │
│  │ 数据写入       │   │ 1.Fuser.fuse │   │                       │ │
│  │ IOProvider    │   │ 2.LLM.ask    │   │                       │ │
│  │               │   │ 3.提取Action  │   │                       │ │
│  └──────────────┘   │ 4.promise()   │   └───────────────────────┘ │
│                      └──────────────┘                              │
│  ┌──────────────┐   ┌──────────────┐   ┌───────────────────────┐ │
│  │ ModeManager   │   │ Background   │   │ SimulatorOrchestrator  │ │
│  │               │   │ Orchestrator │   │                       │ │
│  │ 模式切换管理   │   │ 后台任务调度  │   │ 仿真环境集成           │ │
│  │ 生命周期钩子   │   │              │   │                       │ │
│  └──────────────┘   └──────────────┘   └───────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘

    单个 tick 的详细流程（_tick() 方法）¶

    1. flush_promises — 检查上一轮动作是否完成
    2. Fuser.fuse() — 将所有输入融合为一个 LLM prompt：
    3. 系统提示词 + 治理规则 + 示例 + 当前时间
    4. AVAILABLE INPUTS: (Voice, Vision, GPS, Lidar, Battery...)
    5. KNOWLEDGE BASE: (从 FAISS 检索的相关文档)
    6. AVAILABLE ACTIONS: (所有可用动作的函数签名)
    7. What will you do? Actions:
    8. ModeManager.process_tick() — 检查是否需要切换模式：
    9. 时间触发（timeout → 自动回到默认模式）
    10. 上下文触发（context 条件满足）
    11. 输入触发（语音中包含特定关键词如 "导航"、"回家"）
    12. action_gate 检查 — 如果配置了 action_gate，仅在有 Voice 新输入时才允许 LLM 调用
    13. voice_planner (可选) — 将长语音拆分为多个子语音依次执行
    14. LLM.ask_stream() — 流式调用大模型，返回 Action[]
    15. MCP 循环 (可选) — 支持 MCP 工具调用的多轮 ReAct 循环
    16. ActionOrchestrator.promise() — 执行模型决策的动作

    关键组件详解¶

    组件 文件 职责
    ModeCortexRuntime runtime/cortex.py 总控制器，管理所有异步任务和生命周期
    ModeManager runtime/manager.py 模式状态机，支持 INPUT_TRIGGERED / TIME_BASED / CONTEXT_AWARE / MANUAL 四种切换
    ModeSystemConfig runtime/config.py 配置加载+校验+组件实例化（JSON5 → Python 对象）
    Fuser fuser/__init__.py 将所有 inputs + KB + actions 拼成 LLM prompt
    IOProvider providers/io_provider.py 全局单例，存储所有输入的最新值、tick 计数器、prompt 历史
    ConfigProvider providers/config_provider.py HTTP 配置服务，支持远程配置下发
    SleepTickerProvider providers/sleep_ticker_provider.py Ticker 休眠控制器，支持 mode 切换时跳过休眠

  system_governance: "...",          // 行为治理规则

  modes: {
    greeting: {                      // 模式1: 迎宾
      display_name: "迎宾模式",
      system_prompt_base: "...",
      hertz: 1.0,
      timeout_seconds: 120,          // 超时自动切换
      agent_inputs: [                // 该模式的输入
        {name: "Voice", ...},
        {name: "Vision", ...},
      ],
      cortex_llm: {                  // 该模式的 LLM
        type: "openai",
        model: "gpt-4o",
        config: {api_key: "...", ...}
      },
      agent_actions: [               // 该模式可用的动作
        {name: "speak", ...},
        {name: "hello", ...},        // ARX5 挥手
        {name: "emotion", ...},      // 表情
      ],
    },
    conversation: { ... },           // 模式2: 闲聊
    navigation: { ... },             // 模式3: 导航
  },

  transition_rules: [
    {
      from_mode: "greeting",
      to_mode: "conversation",
      transition_type: "input_triggered",
      trigger_keywords: ["聊天", "对话", "你好"],
      priority: 5,
      cooldown_seconds: 10,
    },
    {
      from_mode: "conversation",
      to_mode: "greeting",
      transition_type: "time_based",
      timeout_seconds: 120,
    },
  ],

  global_lifecycle_hooks: [
    {type: "on_startup", command: "python scripts/init_audio.py"},
  ],
}

    关键是：每个 mode 完全独立配置自己的 inputs、LLM、actions，模式切换时旧的组件被停止，新的组件被实例化。

    模式切换机制¶

    系统支持四种切换触发方式：

    类型 枚举值 触发条件
    输入触发 INPUT_TRIGGERED 语音/输入中包含 trigger_keywords
    时间触发 TIME_BASED 当前 mode 运行时间超过 timeout_seconds
    上下文触发 CONTEXT_AWARE user_context 中满足 context_conditions
    手动切换 MANUAL 通过 API/Zenoh 请求显式切换

    切换时执行的完整的生命周期钩子序列： 

    旧 mode: ON_EXIT hooks → 全局: ON_EXIT hooks
→ 更新 State
→ 新 mode: ON_ENTRY hooks → 全局: ON_ENTRY hooks

    六、完整数据流¶

    外部传感器数据
     │
     ▼
┌──────────────────┐
│  InputOrchestrator │  ← 每个 input 实例异步采集数据，写入 IOProvider
│  (60+ sensors)     │     (单例，按 "Voice"/"Vision"/"GPS" 等 key 索引最新值)
└──────────────────┘
     │
     ▼ (每个 hertz tick，如每秒 1 次)
┌──────────────────┐
│     Fuser.fuse()  │  ← 从 IOProvider 读取所有 input 的最新 buffer
│                    │     + 系统 prompt + 治理规则 + 示例 + 当前时间
│                    │     + FAISS 知识库 RAG 检索 (基于 Voice query)
│                    │     + 当前 mode 所有 action 的 function call schema 描述
│                    │    → 拼接为完整 LLM prompt
└──────────────────┘
     │
     ▼
┌──────────────────┐
│   LLM.ask_stream()│  ← 流式调用大模型 (OpenAI/DeepSeek/Gemini/Grok...)
│   (tool_choice    │     function call 模式: tool_choice="required"
│    ="required")   │    输出: {text, actions: [{type, value}]}
└──────────────────┘
     │
     ▼
┌──────────────────┐
│ ActionOrchestrator│  ← 解析每个 action.type → 查找对应 Action 类
│   .promise()      │    根据 action_execution_mode:
│                    │    - concurrent: asyncio.gather 并行执行
│                    │    - sequential: 按序 await 执行
│                    │    - dependencies: 按 DAG 拓扑排序后执行
└──────────────────┘
     │
     ▼
┌──────────────────┐
│  Action.execute() │  ← 通过 connector (Zenoh/ROS2/Serial/HTTP/WebSocket)

│                    │    - 语音 → TTS 服务播放
│                    │    - 运动 → ROS2 topic 下发
│                    │    - 抓取 → Zenoh → ARX5 控制器 → CAN bus → 电机
└──────────────────┘

    七、与 arx5-sdk 的关系¶

    MAGIC 项目中，ARX5 机械臂的控制采用分层架构：

    ┌──────────────────────────────────────────────────────────────┐
│  MAGIC (AI 大脑层)                                            │
│  ├── LLM 理解用户语音: "把桌上那个红瓶子拿过来"                   │
│  ├── 输出 Action: {type: "arm_x5_grasp",                       │
│  │       value: {target: "a red bottle"}}                     │
│  │                                                            │
│  │  arm_arx_x5_yolograsp action 处理:                          │
│  │  ├── interface.py: 解析 LLM 返回的 target 参数               │
│  │  ├── connector/zenoh.py: 通过 Zenoh 发送抓取请求           │
│  │  ├── utils/planner.py: 编排抓取序列                        │
│  │  └── utils/sample_arm_yolo_grasp_motion.py: 运动轨迹        │
└──────────────────────────────────────────────────────────────┘
     │ (Zenoh / ROS2 通信)
     ▼
┌──────────────────────────────────────────────────────────────┐
│  ARX5 控制中间层 (sample_arm.py 所在的 ROS2 节点)              │
│  ├── ROS2 topic /arm_cmd (RobotCmd)  ← 接收指令               │
│  ├── ROS2 topic /arm_status (RobotStatus) ← 反馈状态           │
│  ├── VisionSystem (YOLO+SAM+GraspNet 视觉检测)                 │
│  │   ├── YOLO 目标检测 (远端服务 172.40.1.67:5004/5009)        │
│  │   ├── SAM 实例分割                                          │
│  │   └── GraspNet 抓取姿态估计 (远端服务 172.40.1.67:5005)      │
│  ├── ArmController (轨迹规划 + 多步抓取序列)                    │
│  │   ├── move_to() — 笛卡尔空间线性插值                          │
│  │   ├── move_joint_to() — 关节空间插值                         │
│  │   └── execute_grasp_sequence_yolo/graspnet() — 完整抓取流程   │
│  └── TaskManager (任务队列 + 三点巡检 + 失败重试)                │
└──────────────────────────────────────────────────────────────┘
     │ (ROS2 → CAN bus)
     ▼
┌──────────────────────────────────────────────────────────────┐
│  arx5-sdk (底层驱动)                                          │
│  ├── Arx5JointController — 关节空间控制 (500Hz)                │
│  ├── Arx5CartesianController — 笛卡尔空间控制 (200Hz)          │
│  ├── SocketCAN → USB-CAN 适配器 → 电机 (EC_A4310 / DM_J4310)   │
│  └── 预编译 .so: libhardware.so + libsolver.so                 │
└──────────────────────────────────────────────────────────────┘

    当前分支 optimize-yolograsp-flow¶

    位于 MAGIC 的 arm_arx_x5_yolograsp action 层，优化内容涉及： - YOLO 检测 → SAM 分割 → GraspNet 抓取姿态估计的流水线 - 三点巡检扫描 + 置信度择优逻辑 - 多步抓取序列（接近 → 抓取 → 撤退 → 放置） - 失败重试策略（YOLO 抓取 → 验证 → GraspNet 二次抓取） - Websocket 回传状态到 MAGIC 主进程

    九、运行流程总结¶

    # 1. 初始化 conda 环境
mamba env create -f conda_environments/py310_environment.yaml

# 2. 安装依赖
uv sync --all-groups

# 3. 启动外部服务 (TTS, ASR, 视觉检测等)
./service/Kokoro-FastAPI/start-gpu.sh &
python service/faster_whisper_asr_server.py &

# 4. 启动 ARX5 控制器 + Zenoh Bridge
ros2 launch arx_x5_controller open_single_arm.launch.py &
python system_hw_test/arx_x5_gripper_zenoh_bridge.py &

# 5. 启动 MAGIC 主程序
uv run src/run.py unitree_go2_koala_welcome

    启动后，系统进入事件循环： 1. 默认 mode 初始化: 加载配置 → hardware preflight 自检 → 启动所有 inputs/LLM/actions 2. Hz tick 循环: 每秒 (可配) 执行一次 sense→think→act 循环 3. 模式切换: 根据用户语音/时间/上下文自动切换 mode 4. 热重载: 定期检查 config/memory/.runtime.json5，变更时无缝重载配置
