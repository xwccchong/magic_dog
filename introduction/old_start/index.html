    启动脚本解析¶

    以/home/unitree/MAGIC/scripts/start_koala_fetch_stack.sh为例

    为宇树 Go2 机器狗搭载 ARX 机械臂（Koala Fetch 项目）编写的 Tmux 自动化多窗口启动 Bash 脚本。

    一、 参数默认数值解析¶

    脚本开头和 resolve_env_values 函数中定义了一系列的核心变量。如果系统环境变量或 ${MAGIC_DIR}/.env 文件中没有指定这些变量，脚本就会使用以下默认数值：

    1. 基础与路径参数¶

    • SESSION_NAME (Tmux会话名): koala_fetch_stack —— 这是创建的 Tmux 后台会话的代号。
    • MAGIC_DIR (主工作目录): /home/unitree/MAGIC —— 项目的核心代码及模型存放根目录。
    • ARX_ROS2_SCRIPT (机械臂ROS2驱动脚本): /home/unitree/unitree_sdk2_python/scripts_v2/start_arx_ros2.sh —— 用来拉起机械臂底层硬件驱动的脚本。
    • CYCLONEDDS_ARX_CONFIG (DDS配置文件): /tmp/cyclonedds_arx_lo.xml —— 用于控制 ROS 2 通信的 CycloneDDS 临时配置文件。

    2. ROS 2 通信参数¶

    • ROS_DOMAIN_ID_VALUE (ROS 2 领域ID): 231 —— 隔离机器人和外部电脑 ROS2 通讯的 ID 标识（确保多台设备间不串号）。
    • ROS_LOCALHOST_ONLY_VALUE (仅限本地通讯): 0 —— 为 0 表示允许跨设备进行网络通信。
    • UNITREE_ETHERNET_VALUE (宇树网卡名): eth0 —— 狗载板子与狗主控通信通常使用的物理网卡。
    • NO_PROXY_VALUE (代理白名单): 127.0.0.1,localhost,127.0.0.1:5000,127.0.0.1:6793,172.40.1.67 —— 过滤掉不需要走代理的网络地址，确保本地通信和特定的局域网 IP（如狗主控 IP 172.40.1.67）不被外部代理拦截。

    3. 音频与语音识别 (ASR) 参数¶

    • ASR_MICROPHONE_NAME_VALUE (麦克风驱动): pulse —— 音频系统（PulseAudio）。
    • ASR_ALSA_CARD_VALUE (音频卡名称): MINI —— 阵列麦克风硬件卡的代号。
    • SHERPA_ONNX_KWS_MODEL_DIR_VALUE (关键词唤醒模型目录): ${MAGIC_DIR}/service/models/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20 —— 离线语音唤醒模型所在的文件夹。
    • 包含的其他模型子文件（如 encoder...int8.onnx、decoder...onnx、joiner...int8.onnx、tokens.txt、keywords.txt）均默认指向该模型目录下的对应具体文件。

    4. 大语言模型 (LLM) 参数¶

    • DASHSCOPE_CHAT_MODEL_VALUE (大模型选型): deepseek-v4-pro —— 默认调用阿里云百炼（DashScope）上的 deepseek-v4-pro 模型作为机器人的交互“大脑”。
    • DASHSCOPE_API_KEY: 无默认值（必填） —— 必须在系统环境变量里 export 或者写入 ${MAGIC_DIR}/.env 文件中，否则前置检查会直接报错退出。

    二、 启动程序流程详解¶

    当你执行 ./script.sh start（或者直接运行且不带参数）时，触发的启动流程如下：

    1. 前置准备与环境加载 (start_stack)¶

    • 加载环境文件：调用 load_env_file，尝试读取 ${MAGIC_DIR}/.env 将配置变量导入。
    • 解析默认值：调用 resolve_env_values 确保所有未被外部设置的变量都拿到上述默认值。
    • 环境强校验 (ensure_prerequisites)：
      • 检查系统是否安装了 tmux、amixer、uv（高性能 Python 包管理器）等命令。
      • 检查所需的 ROS 工作空间路径、Python 脚本以及离线语音模型文件是否存在。
      • 检查 DASHSCOPE_API_KEY 是否配置。如果有任何一项不满足，直接报错退出。
    • 去重防冲突：检查 koala_fetch_stack 会话是否已在后台运行，若已运行则提示用户，不再重复启动。
    • 生成网络配置：动态创建并写入临时 DDS 配置文件 /tmp/cyclonedds_arx_lo.xml，允许组播通信。

    2. Tmux 会话创建与多窗口并行启动¶

    脚本会隐式创建一个 Tmux 并在后台开辟 3 个互相独立的窗口（Windows），依次输入命令：

    窗口 0：arx_ros2（机械臂底层驱动）¶
    • 目的：初始化机械臂通信与控制。
    • 执行指令： bash bash '/home/unitree/unitree_sdk2_python/scripts_v2/start_arx_ros2.sh' 拉起机械臂控制的 CAN 驱动、对应的 ROS2 硬件节点等底层基础服务。
    窗口 1：arx_bridge（机械臂与外界的桥梁）¶
    • 目的：建立一个基于 Zenoh 通信协议的运动控制桥梁，实现无缝控制。
    • 执行指令：
      1. 清除潜在冲突的环境变量（ROS_DISTRO, LD_PRELOAD, PYTHONPATH）。
      2. source /opt/ros/foxy/setup.bash (加载 ROS Foxy 环境)。
      3. source /home/unitree/ARX_X5/ROS2/X5_ws/install/local_setup.bash (加载 ARX 机械臂的 ROS2 工作空间)。
      4. 配置 ROS_DOMAIN_ID=231 和 CycloneDDS 路径。
      5. 运行： bash python3.8 system_hw_test/arx_x5_motion_zenoh_bridge.py --standalone-discovery 使机械臂能够通过 Zenoh 协议或者独立发现模式接收运动指令。
    窗口 2：koala_fetch（核心大逻辑：机器狗抓取业务 + 语音交互）¶
    • 目的：拉起机器狗整体业务逻辑。
    • 执行指令：
      1. 进入 ${MAGIC_DIR} 目录。
      2. 依次 source 加载 Foxy 环境、CycloneDDS 工作空间、OM1 狗载端 SDK 空间、以及机械臂 ROS2 空间。
      3. 注入各类语音识别（Sherpa-onnx）、网卡（eth0）、大模型等环境变量。
      4. 通过 amixer 将外接的音频设备放音音量设为 100% 并取消静音。
      5. 清空外部代理（防止代理导致请求无法发送到外网的大模型 API 或干扰本地通信）。
      6. 最后使用 uv 极其轻量地启动核心逻辑： bash uv run --no-sync python src/run.py unitree_go2_koala_fetch_modes 运行项目大逻辑，机器狗正式进入等待语音关键词唤醒并执行抓取任务的状态。

    3. 终收尾与界面切换¶

    • 最后，脚本通过 tmux select-window 将默认焦点切换到 koala_fetch 这个业务窗口（方便你一挂载进 Tmux 就能看到大模型的交互和核心日志）。
    • 并在桌面上打印提示信息，告诉你已经成功创建了后台会话，你可以通过： bash tmux attach -t koala_fetch_stack 随时进入这个后台环境去查看机械臂、机器狗、大模型的实时运行状态和报错。
