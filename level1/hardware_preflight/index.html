    hardware_preflight.py 文件详解¶

    文件路径：/home/nvidia/MAGIC/src/runtime/hardware_preflight.py

    这个文件负责在系统启动前探测硬件可用性，并自动禁用依赖缺失硬件的组件，避免运行时错误。

    数据类¶

    HardwareCheck¶

    定义位置：第 16-21 行

    作用：单次硬件探测结果。

    @dataclass
class HardwareCheck:
    name: str        # 硬件名称
    passed: bool     # 是否通过
    detail: str = "" # 详细信息

    示例： 

    check = HardwareCheck("D435(camera_0)", True, "RealSense serial 12345 found")

    HardwarePreflightReport¶

    定义位置：第 24-31 行

    作用：硬件预检报告汇总。

    @dataclass
class HardwarePreflightReport:
    checks: list[HardwareCheck] = field(default_factory=list)              # 所有检查项
    available_capabilities: dict[str, bool] = field(default_factory=dict)  # 可用能力映射
    disabled_inputs: list[str] = field(default_factory=list)               # 被禁用的输入
    disabled_backgrounds: list[str] = field(default_factory=list)          # 被禁用的后台
    disabled_actions: list[str] = field(default_factory=list)              # 被禁用的动作

    核心类¶

    HardwarePreflightProbe¶

    定义位置：第 58-152 行

    作用：硬件探测器的默认实现，提供具体的硬件检测方法。

    方法 1: has_realsense_device(serial_number=None)¶

    作用：检测 RealSense 相机是否可用。

    参数： - serial_number: Optional[str] - 指定的序列号（可选）

    返回值： - tuple[bool, str] - (是否可用, 详细信息)

    流程： 

    1. 尝试导入 pyrealsense2
   ↓
2. 查询所有 RealSense 设备
   ↓
3. 如果没有指定序列号 → 返回设备数量
   ↓
4. 如果指定序列号 → 检查是否匹配
   ↓
5. 返回检测结果

    示例： 

    probe = HardwarePreflightProbe()

# 检查任意 RealSense 设备
available, detail = probe.has_realsense_device()
# → (True, "2 RealSense device(s) found")

# 检查特定序列号
available, detail = probe.has_realsense_device(serial_number="12345")
# → (True, "RealSense serial 12345 found")

    方法 2: has_fresh_arx_state(topic, timeout_seconds, max_age_seconds, required_fields)¶

    作用：检测 ARX X5 机械臂是否在发布新鲜的状态数据。

    参数： - topic: str - Zenoh 状态主题 - timeout_seconds: float - 超时时间 - max_age_seconds: float - 状态最大年龄 - required_fields: Optional[list[str]] - 必需字段列表

    返回值： - tuple[bool, str] - (状态是否新鲜, 详细信息)

    流程： 

    1. 尝试导入 zenoh_msgs
   ↓
2. 打开 Zenoh 会话
   ↓
3. 订阅状态主题
   ↓
4. 等待接收状态消息（最多 timeout_seconds）
   ↓
5. 检查必需字段是否存在
   ↓
6. 检查状态时间戳是否新鲜
   ↓
7. 关闭订阅和会话
   ↓
8. 返回检测结果

    示例： 

    available, detail = probe.has_fresh_arx_state(
    topic="arx_x5/state",
    timeout_seconds=2.0,
    max_age_seconds=2.0,
    required_fields=["joint_pos"]
)
# → (True, "fresh state received with fields: joint_pos; state age=0.152s")

    核心函数¶

    format_hardware_preflight_report¶

    定义位置：第 34-54 行

    作用：将硬件预检报告格式化为可读字符串，用于 LLM 提示和语音回复。

    参数： - report: HardwarePreflightReport - 预检报告

    返回值： - str - 格式化后的报告

    输出示例： 

    硬件自检结果：
- D435(camera_0)：正常（RealSense serial 12345 found）
- ARX X5 motion (arx_x5/state)：正常（fresh state received with fields: joint_pos）
已禁用输入：D435RealSenseInput(camera_id=camera_1)
已禁用动作：grasp_object

    apply_hardware_preflight¶

    定义位置：第 154-213 行

    作用：主入口函数，探测硬件并移除依赖缺失硬件的组件。

    参数： - mode_config: Any - 模式配置对象 - probe: Optional[HardwarePreflightProbe] - 自定义探测器（可选）

    返回值： - HardwarePreflightReport - 预检报告

    流程：

    apply_hardware_preflight(mode_config)
        │
        ▼
    检查 mode_config 是否有必需属性
     └── 否 → 返回空报告
        │
        ▼
    _restore_original_raw_config()  ← 恢复原始配置
        │
        ▼
    检查硬件预检是否启用
     └── 否 → 返回空报告
        │
        ▼
    _probe_configured_capabilities()  ← 探测配置的能力
        │
        ▼
    获取 D435 相机能力
     └── 如果未配置 → _probe_d435_backgrounds() ← 自动探测 D435
        │
        ▼
    检查是否需要 ARX 机械臂
     └── 需要 → has_fresh_arx_state() ← 探测 ARX 状态
        │
        ▼
    过滤 _raw_inputs    ← 移除不可用的输入
        │
        ▼
    过滤 _raw_backgrounds ← 移除不可用的后台
        │
        ▼
    过滤 _raw_actions   ← 移除不可用的动作
        │
        ▼
    _log_report()       ← 记录日志
        │
        ▼
    返回预检报告

    辅助函数¶

    _restore_original_raw_config¶

    定义位置：第 216-228 行

    作用：恢复原始配置，支持多次调用预检函数。

    逻辑： - 首次调用时，深拷贝原始配置并保存 - 后续调用时，从保存的副本恢复

    为什么要这样设计？

    第一次调用 apply_hardware_preflight()
    ↓
_restore_original_raw_config()  ← 保存原始配置
    ↓
移除不可用的组件（修改 _raw_inputs 等）
    ↓
返回报告

--- 如果用户再次调用 ---

第二次调用 apply_hardware_preflight()
    ↓
_restore_original_raw_config()  ← 恢复原始配置！
    ↓
再次移除不可用的组件
    ↓
返回报告

    核心目的：确保每次预检都从原始配置开始，而不是从上一次修改后的配置开始。

    _hardware_preflight_disabled¶

    定义位置：第 231-232 行

    作用：检查硬件预检是否被禁用。

    return isinstance(preflight_config, dict) and preflight_config.get("enabled") is False

    _probe_configured_capabilities¶

    定义位置：第 235-274 行

    作用：探测配置文件中显式声明的能力。

    支持的探测类型：

    探测类型 调用方法
    realsense probe.has_realsense_device()
    zenoh_state probe.has_fresh_arx_state()

    执行流程：

    _probe_configured_capabilities(preflight_config, probe, report)
        │
        ▼
    检查 enabled 字段
     └── False → return False（不探测）
        │
        ▼
    提取 capabilities 字典
        │
        ▼
    遍历每个 capability
        │
        ├──► probe_name == "realsense"
        │    → 调用 probe.has_realsense_device()
        │    → 更新 report.available_capabilities
        │    → 添加 HardwareCheck 到 report.checks
        │
        ├──► probe_name == "zenoh_state"
        │    → 调用 probe.has_fresh_arx_state()
        │    → 更新 report.available_capabilities
        │    → 添加 HardwareCheck 到 report.checks
        │
        └──► 其他 probe_name
             → 标记为不可用
        │
        ▼
    return True

    _mode_uses_arx_motion¶

    定义位置：第 314-330 行

    作用：检查模式是否使用 ARX 机械臂运动功能。

    检查逻辑： - 后台：ARXX5YoloGraspExecutor 的运动配置 - 动作：arm_x5_reset, arm_x5_joint_nudge, hello, grasp_object

    _arx_state_probe_settings¶

    返回值： - tuple[str, float, float] - (主题, 超时, 最大年龄)

    _grasp_camera_id¶

    定义位置：第 355-359 行

    _input_enabled¶

    定义位置：第 362-386 行

    作用：判断输入组件是否应启用。

    返回值： - True = 启用该组件 - False = 禁用该组件

    判断逻辑：

    _input_enabled(input_config, d435_capabilities, report)
        │
        ▼
    有 requires_capabilities 字段?
     ├── Yes → 检查所有能力是否满足
     │         └── 满足 → True
     │         └── 不满足 → False
     │
     └── No ↓
        │
        ▼
    type == "D435RealSenseInput"?
     ├── No → return True  ← 与 D435 无关，直接启用
     │
     └── Yes ↓
        │
        ▼
    d435_capabilities[camera_id] == True?
     ├── Yes → return True  ← 相机可用，启用
     │
     └── No → return False  ← 相机不可用，禁用

    设计理念： - 非 D435 相关的输入组件不依赖 D435 相机，所以直接启用 - 如果其他输入有自己的硬件依赖，应该通过 requires_capabilities 字段显式声明

    _background_enabled¶

    定义位置：第 388-418 行

    作用：判断后台组件是否应启用。

    判断逻辑： 1. 检查 requires_capabilities 字段 2. 如果是 D435，检查相机是否可用 3. 如果是 ARXX5YoloGraspExecutor，检查 ARX 是否可用

    _action_enabled¶

    定义位置：第 421-450 行

    作用：判断动作组件是否应启用。

    判断逻辑： 1. 检查 requires_capabilities 字段 2. 如果是 grasp_object，检查 ARX 和相机是否都可用 3. 如果是 ARX 运动动作，检查 ARX 是否可用

    _requires_capabilities¶

    定义位置：第 453-459 行

    作用：提取组件的 requires_capabilities 字段。

    _requirements_satisfied¶

    定义位置：第 462-484 行

    作用：检查能力需求是否满足。

    逻辑： - 遍历所有需求的能力 - 如果有缺失，将组件添加到禁用列表并记录警告

    _config_dict¶

    定义位置：第 486-488 行

    作用：安全获取配置字典。

    _arx_state_freshness_detail¶

    定义位置：第 491-510 行

    作用：检查 ARX 状态数据的新鲜度。

    检查逻辑： 1. 提取时间戳（_received_local_at 或 received_at） 2. 计算数据年龄 3. 判断是否超过最大年龄 4. 检查时间戳是否在未来

    _log_report¶

    设计要点¶

    1. 渐进式禁用¶

    只禁用依赖缺失硬件的组件，其他组件正常运行。

    2. 配置恢复¶

    支持多次调用预检函数，每次都从原始配置开始。

    3. 自动探测¶

    即使没有显式配置 hardware_preflight，也会自动探测 D435 和 ARX。

    4. 能力声明¶

    组件可通过 requires_capabilities 字段声明依赖的能力。

    5. 新鲜度检查¶

    对 ARX 状态数据检查时间戳，确保数据是新鲜的。

    配置示例¶

    启用硬件预检：¶

    {
  hardware_preflight: {
    enabled: true,
    capabilities: {
      "camera:d435:left": {
        probe: "realsense",
        serial_number: "12345"
      },
      "camera:d435:right": {
        probe: "realsense",
        serial_number: "67890"
      },
      "arm:arx_x5:motion": {
        probe: "zenoh_state",
        topic: "arx_x5/state",
        timeout_seconds: 2.0,
        max_age_seconds: 2.0,
        required_fields: ["joint_pos"]
      }
    }
  }
}

    组件声明能力依赖：¶

    {
  agent_inputs: [
    {
      type: "D435RealSenseInput",
      requires_capabilities: ["camera:d435:left"],
      config: { camera_id: "left" }
    }
  ],
  agent_actions: [
    {
      llm_label: "grasp_object",
      requires_capabilities: ["arm:arx_x5:motion", "camera:d435:left"]
    }
  ]
}

    预检报告示例：¶

    report = HardwarePreflightReport(
    checks=[
        HardwareCheck("camera:d435:left", True, "RealSense serial 12345 found"),
        HardwareCheck("camera:d435:right", False, "RealSense serial 67890 not found"),
        HardwareCheck("arm:arx_x5:motion", True, "fresh state received"),
    ],
    available_capabilities={
        "camera:d435:left": True,
        "camera:d435:right": False,
        "arm:arx_x5:motion": True,
    },
    disabled_inputs=["D435RealSenseInput(camera_id=right)"],
    disabled_backgrounds=["D435(camera_id=right)"],
    disabled_actions=["grasp_object"]  # 因为需要两个能力，其中一个不可用
)

    在 config.py 中的使用¶

    from runtime.hardware_preflight import apply_hardware_preflight

# 在模式加载后调用
report = apply_hardware_preflight(mode_config)

# 将报告格式化后注入到系统提示
if report.checks:
    prompt_variable = format_hardware_preflight_report(report)
    # 注入到 LLM 提示中
