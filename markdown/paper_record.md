# SayCan
聚焦于**机器人学中的语言接地（language grounding）与长时程任务规划**问题：如何让机器人理解人类给出的抽象、自然语言指令，并将其分解成一系列当前机器人**能够执行、且在当前环境中可行**的动作。

## 解决的问题
更具体地说，机器人已经拥有一些训练好的低层技能，例如：

+ 找到海绵；
+ 拿起海绵；
+ 移动到水槽；
+ 把海绵放下；
+ 打开抽屉；
+ 把物体放入抽屉。

但这些技能本身通常只能完成短小、原子化的动作。真正困难的是，用户给出的指令往往是高层次、抽象的，例如“把厨房整理一下”“给我拿点运动后适合吃的东西”。机器人需要判断：

1. 用户到底想完成什么；
2. 应该先执行哪些子任务；
3. 这些子任务是否符合当前场景；
4. 机器人当前是否有能力完成这些子任务；
5. 多个动作之间应该按照什么顺序执行。

文章将这个问题概括为：语言模型能够提供高层语义知识，但它没有真实世界经验，因此并不天然知道某个动作在当前机器人和当前环境中是否可行。

## 前人工作
### 直接使用语言模型生成行动计划
核心：缺乏物理知识，语言模型通常只关注“这个动作在语义上是否合理”

一种自然方法是直接询问语言模型，让它把高层指令拆成一系列步骤。例如：

“我想把苹果拿给你，机器人应该怎么做？”

语言模型可能生成：

1. 去商店买苹果；
2. 拿起苹果；
3. 把苹果交给用户。

这类方法能够利用语言模型的常识和语义推理能力，但问题是，生成的动作不一定属于机器人可执行的动作集合。文章指出，仅靠 prompt engineering 虽然可以让语言模型尝试输出分步骤计划，但仍不能完全保证输出只包含机器人可执行的原子技能，也不能保证动作适合当前场景。

### 直接让策略网络理解整条自然语言指令
另一种思路是训练一个语言条件策略，让策略网络直接接收完整的高层指令，然后直接控制机器人。

这种方法避免了显式规划，但要求策略网络同时解决：

+ 语言理解；
+ 子任务分解；
+ 长时程规划；
+ 视觉感知；
+ 低层运动控制。

文章中的消融实验显示，直接把完整指令输入行为克隆策略的基线，即 BC NL，在所有任务上的成功率都是 $0\%$。这说明仅依靠低层策略直接解释复杂高层指令，很难处理抽象和长时程任务。

### 用语言嵌入把高层指令映射到已有技能
还有一种方法是使用通用句子编码器，把用户指令、技能描述以及可能的技能序列映射到向量空间，然后选择语义相似度最高的技能或动作序列。

这种方法比完全直接控制更容易实现，但它主要依赖静态的语义相似度，不一定能处理：

+ 当前环境中某个动作是否可行；
+ 物体是否真的存在；
+ 动作执行是否会成功；
+ 当前机器人状态是否允许执行该动作。

在文章的 BC USE 基线中，这种方法对于单步任务可以取得一定效果，但对于更复杂的任务整体表现很差：单步自然语言任务执行成功率为 $60\%$，而其他任务基本为 $0\%$。

### 只根据语言模型分数选择技能
即使限制语言模型只能在机器人已有技能中选择，如果只选择语言模型认为“最符合指令”的技能，仍可能出现问题。

例如，用户说“把苹果拿给我”，语言模型可能认为下一步是“拿起苹果”；但如果苹果根本不在当前视野中，或者机器人已经拿着苹果，那么这个动作就不合适。因此，语言层面的合理性并不等于物理世界中的可行性。

## 如何解决问题
这篇文章提出的方法叫 **SayCan**。它的核心思想是把两个概率结合起来：

1. **Say：语言模型判断某个技能是否有助于完成用户指令；（思考需要调用哪些工具/技能）**
2. **Can：价值函数判断机器人在当前状态下能否成功执行这个技能。（有点像executor判断schema是否合理，以及obs反馈？）**

最终，机器人选择一个同时满足“有用”和“可执行”的技能。

### Say：语言模型提供任务接地
假设用户给出的高层指令是 $i$，机器人已有技能的语言描述是 $\ell_\pi$，例如：

+ “find a sponge”；
+ “pick up the sponge”；
+ “go to the sink”；
+ “put down the sponge”。

语言模型计算每个技能描述在当前任务下成为下一步动作的概率，**从语言和任务语义上看，该技能是不是一个合理的下一步**

### **Can：价值函数提供世界接地**
:::info
可供性分析，打分函数

:::

**另一方面，机器人使用一个语言条件价值函数判断某个技能在当前状态 $s$ 下是否可行**

_p_(_c_π_∣_s_,ℓ__π_)

这里的输入多了状态（这里会是多元的信息？），来判断是否可行

这个价值函数可以考虑：

+ 当前视觉观察；
+ 物体是否出现在场景中；
+ 机器人当前的位置；
+ 机器人是否已经拿着物体；
+ 当前技能是否适合当前状态。

### 两者相乘进行技能选择
SayCan 将语言模型分数和 affordance 分数相乘；文章把前者称为 **task grounding**，把后者称为 **world grounding**。SayCan 的关键就在于同时进行这两种接地。

### 逐步闭环执行
有点像uncertainty判断的进阶

SayCan 并不是一次性生成完整计划后就完全不再检查，而是采用迭代式过程：

1. 接收用户高层指令；
2. 对所有候选技能计算语言模型分数；
3. 根据当前状态计算 affordance 分数；
4. 将两者相乘；
5. 选择组合得分最高的技能；
6. 执行这个技能；
7. 更新机器人状态；
8. 将已经执行的技能加入语言模型上下文；
9. 继续选择下一个技能；
10. 直到语言模型输出终止动作，例如 “done”。

#### 不需要重新训练语言模型
SayCan 没有针对每一个新任务重新训练大语言模型，而是把机器人已有技能的语言描述作为候选输出，让语言模型对这些候选技能进行打分

#### 语言模型变强可以直接提升机器人表现


# Motus: A Unified Latent Action World Mode
聚焦于**具身智能（embodied intelligence）中的通用机器人操作学习问题**：如何让一个机器人模型同时具备视觉理解、未来状态预测、动作生成、逆动力学建模和视频生成能力，并且能够从互联网视频、人类演示、多机器人轨迹等异构数据中学习，最终迁移到具体机器人上执行操作任务。

## 解决的问题
+ 传统机器人系统通常把以下能力拆成多个独立模型：
    - **视觉语言动作模型（VLA）**：根据当前图像和语言指令预测动作；
    - **世界模型（World Model, WM）**：给定当前状态和动作，预测未来视觉状态；
    - **逆动力学模型（Inverse Dynamics Model, IDM）**：给定连续观察，反推出机器人动作；
    - **视频生成模型（Video Generation Model, VGM）**：根据当前图像和语言生成可能的未来视频；
    - **视频—动作联合预测模型**：同时预测未来视频和动作。
+ 另一个问题是**动作标注数据稀缺且机器人之间动作空间不一致**。（这个是核心贡献）

互联网视频和人类第一视角视频包含大量运动与交互信息，但通常没有机器人动作标签；不同机器人在动作维度、控制范围、机械结构和传感器配置上也不同，因此一个机器人采集的动作不能直接用于另一个机器人。

## 如何解决问题

### 用Mixture-of-Transformers统一三个专家
Motus不是把所有功能简单地塞进同一个Transformer，而是保留三个具有不同职责的专家：

1. **理解专家**：负责视觉、语言、空间和物体理解；
2. **视频生成专家**：负责预测未来视觉状态；
3. **动作专家**：负责生成机器人动作或潜在动作。

其中：

+ 视频生成专家使用预训练的[Wan](/abs/2503.20314?chatId=01a022fd-9805-7a17-8004-899ef6236533)模型；
+ 理解专家使用Qwen系列视觉语言模型；
+ 动作专家采用与视频专家相匹配的Transformer结构。

三个专家保留各自的功能模块，但共享多头自注意力层，形成论文提出的**Tri-model Joint Attention（三模型联合注意力）**。这样做的目的，是让视觉、语言、视频和动作信息能够跨模态交互，同时避免把所有任务完全混合后造成严重的任务干扰。

### 用UniDiffuser风格的调度器切换不同模式
Motus同时对视频和动作进行扩散或rectified-flow式建模，但为视频和动作分配不同的噪声时间步和噪声尺度。

这使得同一个模型可以在推理时切换不同模式：

+ **VLA模式**：输入当前图像和语言，输出动作；
+ **世界模型模式**：输入当前图像和动作，生成未来视频；
+ **IDM模式**：输入观察序列，预测动作；
+ **VGM模式**：输入当前图像和语言，生成未来视频；
+ **视频—动作联合预测模式**：同时生成未来视频和动作。

本质上，Motus不是为每种任务训练一个独立模型，而是通过改变哪些变量保持干净、哪些变量从噪声开始采样，来实现不同条件分布之间的切换。

### 视频稀疏、动作密集的预测策略
如果视频和动作都以相同频率预测，视频token数量会远远多于动作token，模型容易过度关注视频生成而忽略动作预测。Motus因此降低视频帧率，使视频token和动作token数量更加平衡。例如，论文中将视频帧率设置为动作帧率的约六分之一。

### 光流潜在动作
Motus最有代表性的创新之一，是使用**光流（optical flow）学习潜在动作**。

### 4.1 为什么使用光流？
连续视频帧之间的光流描述了像素级运动：

+ 物体向哪里移动；
+ 机械臂如何移动；
+ 手和物体之间如何发生相对运动；
+ 场景中的局部变化在哪里发生。

与直接重建RGB图像相比，光流更关注运动变化，而不是颜色、纹理和背景外观。因此，它更适合表示与机器人控制相关的动态信息。

Motus首先利用DPFlow计算光流，然后将光流转换为RGB形式，再用深度压缩自编码器进行压缩。编码器最终把光流压缩为4个512维token，并进一步映射成一个约14维的潜在动作向量，使其维度大致接近典型机器人的动作空间。

### 第一阶段：学习视觉动态
首先利用网页视频、人类视频、合成数据和多机器人轨迹训练视频生成专家，使其学习物体运动、接触变化和任务执行中的视觉动态。

这一阶段主要回答：

在某个场景和语言指令下，未来可能发生什么？

### 第二阶段：学习潜在动作
随后冻结视觉语言理解专家，联合训练整个Motus模型，让动作专家从视频、语言和潜在动作中学习运动模式。

这一阶段的重点是把：

$$   
\text{视觉变化}\rightarrow\text{潜在运动}\rightarrow\text{动作表示}  
$$

连接起来，从而使动作专家不仅依赖少量带动作标签的机器人轨迹，还能从大量无动作标签视频中获得运动先验。

### 第三阶段：适配目标机器人
最后使用目标机器人的轨迹进行监督微调，使通用运动先验适应特定机器人的机械结构、运动学和控制接口。



# flow matching
**生成模型中的连续归一化流（Continuous Normalizing Flows, CNFs）训练问题**：如何在高维图像上高效、稳定地训练一个连续时间生成模型，并且用较少的计算成本完成采样。

CNF 不像普通神经网络那样通过有限层变换数据，而是用一个随时间变化的神经网络向量场 $v_t(x)$ 定义连续动力系统：

$$   
\frac{d}{dt}\phi_t(x)=v_t(\phi_t(x)).  
$$

从 $t=0$ 到 $t=1$，这个常微分方程（ODE）把噪声分布 $p_0$ 推送成目标数据分布 $p_1$。

问题在于在训练极端需要反复进行ODE数值模拟；而传统的扩散过程就死求解SDE或者ODE方程



### 扩散模型：通过逐步加噪和去噪训练
另一条主流路线是扩散模型，例如 DDPM 和 [Score-Based Generative Modeling through Stochastic Differential Equations](/abs/2011.13456?chatId=01a03d36-8bce-701e-a5ea-8e515734ecd0)。

扩散模型通常从数据出发，逐渐加入噪声，再学习如何反向去噪。训练时并不直接学习完整的生成轨迹，而是学习某个时间点上的条件噪声、score function 或去噪方向。例如，对于一个高斯条件路径：

$$   
p_t(x\mid x_1) = \mathcal{N}\big(x\mid \mu_t(x_1),\sigma_t^2(x_1)I\big),  
$$

扩散模型通常回归：

+ score，即 $\nabla_x\log p_t(x\mid x_1)$；
+ 或者噪声变量；
+ 或者与扩散过程相关的向量场。

这使扩散模型能够稳定地训练，并且比传统 CNF 更容易扩展到高维图像。不过，扩散方法仍然存在两个限制：

1. 它依赖一类特定的随机扩散过程；
2. 采样时通常需要很多时间步或大量网络函数评估（NFE）。

### Flow Matching：直接回归目标向量场
:::info
通过回归产生目标概率路径的向量场，而不是在训练中模拟生成轨迹。

:::

假设我们已经指定了一条概率密度路径 $p_t(x)$，并且存在一个向量场 $u_t(x)$，它能够生成这条概率路径。

本文不再通过模拟 ODE 来训练模型，而是直接让神经网络 $v_t(x;\theta)$ 回归这个目标向量场：

$$   
\mathcal{L}_{\mathrm{FM}}(\theta) = \mathbb{E}_{t,p_t(x)} \left[ \left\| v_t(x;\theta)-u_t(x) \right\|^2 \right].  
$$

直观地说，模型在随机抽取的时间 $t$ 和位置 $x$ 上，直接学习“此时此地应该朝哪个方向移动”。

这种方式的优点是，训练样本只需要：

1. 采样一个时间 $t$；
2. 采样一个数据样本；
3. 构造对应时刻的状态 $x_t$；
4. 计算目标速度 $u_t(x_t)$；
5. 进行普通的均方误差回归。

因此训练过程类似监督学习，而不是每次都求解完整 ODE。

## 训练过程使用条件flow matching；
对于每一个数据样本都能构造出对应的条件概率路径，那么对于数据样本的分布，就能生成边际概率路径

如果每个条件向量场 $u_t(x\mid x_1)$ 能生成对应的条件概率路径，那么按照上述方式聚合后得到的边际向量场，就能生成边际概率路径。

### 扩散路径也可以被 Flow Matching 统一处理
论文并没有完全否定扩散路径。它证明，常见的 VE、VP 等扩散概率路径都可以放进 Flow Matching 框架中。

这带来一个统一视角：

+ 扩散模型可以看成在特定概率路径上进行向量场或 score 学习；
+ Flow Matching 则允许直接选择更一般的概率路径；
+ 因此，扩散路径只是 FM 可以使用的一类特殊路径，而不是唯一选择。

### Optimal Transport 路径
x0 是初始高斯噪声。这个表达式意味着：噪声部分逐渐减弱，数据方向逐渐增强。

令均值和标准差随时间线性变化：

$$   
\mu_t(x_1)=tx_1,  
$$

$$   
\sigma_t(x_1) = 1-(1-\sigma_{\min})t.  
$$

对应的条件流为：

$$   
\psi_t(x_0) = \big(1-(1-\sigma_{\min})t\big)x_0 + tx_1.  
$$

<font style="background-color:#FBDE28;">这里的条件流是指当前的变化量；对应的速度需要对t进行求导；然后就可以和速度作loss进行训练</font>

### 为什么 OT 路径更好？
对于条件分布而言，$\psi_t$ 是两个高斯分布之间的 OT 位移映射。OT 位移插值具有以下特点：

1. **轨迹是直线的**；
2. **运动速度基本恒定**；
3. **不会出现明显的回溯或 overshoot**；
4. **向量场随时间变化更加简单**；
5. **模型更容易学习，ODE 求解器也可以用更少的函数评估完成采样**。

论文特别指出，扩散路径的轨迹可能出现“超过最终位置后再回头”的现象，而 OT 路径保证条件粒子沿直线运动。OT Trajectories

需要注意的是，论文也强调：<font style="background-color:#FBDE28;">条件流是 OT，并不意味着最后得到的边际向量场一定是完整数据分布上的全局最优传输解。OT 的“最优”主要体现在每个条件路径的构造上。</font>

### <font style="background-color:#FBDE28;">DDIM</font>
训练时仍然使用 DDPM 的扩散目标，但采样时不一定按照原来的随机、逐步加噪—去噪过程，而是构造一条**确定性的非马尔可夫采样轨迹**，从而可以跳过部分时间步。

<font style="background-color:#FBDE28;">DDIM 的“少步采样”本质上是对原始连续或离散生成轨迹进行较粗的数值近似，因此步数越少，通常误差越大，图像质量也可能下降。</font>

**保留同一个训练好的扩散模型，但改变采样过程**。它可以使用一个确定性更新规则



### 为什么 Flow Matching 也可以少走几步？
Flow Matching 的采样过程是求解一个 ODE：

$$   
\frac{d x_t}{dt}=v_t(x_t),  
$$

其中 $v_t$ 是训练得到的速度场。采样时从噪声 $x_0$ 出发，通过 ODE 求解器推进到 $t=1$：

$$   
x_0\rightarrow x_{t_1}\rightarrow x_{t_2}\rightarrow \cdots \rightarrow x_1.  
$$

所谓“去噪步数”，在 Flow Matching 中更准确地说是 **ODE 求解步数**或 **函数评估次数（NFE）**。每一步都调用一次或多次网络 $v_t$，估计当前状态应该往哪个方向移动。

关键在于：Flow Matching 训练的不是某几个固定去噪步骤，而是整个时间区间上的连续速度场。因此，训练后模型可以在任意时间 $t$ 查询

:::info
有点类似于预测出一个函数还是函数对应的离散的数值

:::

1. 时间是连续的，不依赖固定步数：采样时可以自由选择时间网格；只要 ODE 求解器在相邻两个时间点之间能够较好地近似轨迹，就可以直接使用较少的步数
2. Flow Matching，尤其是 FM-OT，学习的轨迹更直：样本从噪声走向数据时，主要沿着一条直线移动，速度变化较简单。论文指出，OT 位移路径具有直线轨迹和近似恒定速度，而扩散路径可能发生弯曲甚至 overshoot。

**不用按照训练时或传统扩散模型规定的全部时间步逐步生成，而是选择一个更稀疏的时间网格，让 ODE 求解器跨越较大的时间区间。**

### **为什么 Flow Matching 比传统扩散更适合少步采样？**
**可以从轨迹形状理解。**

#### **传统扩散路径**
**扩散模型的生成路径通常具有明显的非均匀性：**

+ **某些时间段变化很慢；**
+ **某些时间段变化很快；**
+ **轨迹可能弯曲；**
+ **图像信息可能在较晚阶段才明显出现。**

**因此，如果使用很大的步长，容易跳过关键变化区域。论文在 ImageNet 实验中观察到，扩散路径生成的图像往往直到后期才显著去除噪声。****Sampling Paths**

#### **FM-OT 路径**
**FM-OT 直接选择更加简单的 OT 条件路径，使噪声和数据之间的变化更加平滑、规整。论文报告，在 ImageNet-32 上，FM-OT 达到与扩散模型相近的数值误差，大约只需要扩散模型 ****60% 的 NFE****。****Fewer Evaluations**

**因此，Flow Matching 少步采样的根本原因不是“去噪步骤可以随意删除”，而是：**

1. **学到了一个在整个时间区间内可查询的连续向量场；**
2. **该向量场对应的概率路径比较平滑；**
3. **OT 路径使条件轨迹更直；**
4. **平滑轨迹更容易被大步长 ODE 积分器近似。**

### DDIM 和 Flow Matching 的共同点与区别
两者都可以通过跳过部分时间步来加速生成，但原理略有不同。

**共同点**是：

+ 都不一定需要执行最初设计的全部采样步；
+ 都可以使用确定性的生成轨迹；
+ 都把采样看成从噪声到数据的数值演化；
+ 步数减少后，计算量下降，但离散化误差可能增加。

**区别**是：

+ DDIM 通常是在已经训练好的扩散模型基础上，重新设计一个更快的采样更新公式；
+ Flow Matching 从训练阶段就直接学习连续速度场；
+ DDIM 所对应的扩散轨迹通常仍可能比较弯曲；
+ FM-OT 从一开始就尝试构造更直、更简单的概率路径。

可以这样类比：

DDIM 更像是“原本有一条很长的扩散路线，现在挑选其中一些站点，跳站行驶”；  
Flow Matching 更像是“直接学习一张从噪声到数据的连续路线图，并且尽量让这条路线变直”。

类似于D的曲边和直边

## EDM
确实可以像 DDIM 或 Flow Matching 一样，通过减少采样时间步来加速生成；但它实现跳步的核心并不是 Flow Matching 的“直接回归速度场”，而是对扩散模型的连续噪声轨迹、ODE 求解器和噪声调度进行了重新设计。

EDM 不是一种完全不同于扩散模型的新生成范式，更准确地说，它是对扩散模型中多个设计选择的系统重构：

1. 如何表示噪声水平 $\sigma$；
2. 如何训练去噪网络；
3. 如何对网络输入、输出进行预条件化；
4. 如何选择采样时的噪声时间表；
5. 如何选择 ODE 数值求解器；
6. 是否在采样过程中重新注入随机噪声。

论文的观点是，传统扩散模型往往把这些选择和某个特定的 SDE、训练目标、采样器绑定得太紧。EDM 将它们拆开，认为可以分别优化。

+ 使用的是连续噪声强度

### 为什么 EDM 使用 Heun，而不是简单 Euler？
Euler 更新是：

$$   
x_{i+1} = x_i+ (\sigma_{i+1}-\sigma_i)d_i,  
$$

其中 $d_i$ 是当前噪声水平下的预测方向。

问题是：在这一步之内，速度方向可能发生变化。Heun 方法会先用 Euler 得到一个临时结果，再在终点重新调用一次网络，得到新的方向 $d_i'$，最后取平均；这样相当于估计了一个区间内的平均速度，而不只是使用区间起点的速度。论文称这种方法为二阶 Heun 方法，并认为它在网络评估次数和采样误差之间取得了很好的平衡。



<font style="background-color:#FBDE28;">EDM 更强调让网络输出一个尺度合理、数值稳定的去噪结果。</font>

<font style="background-color:#FBDE28;">EDM 把采样看成一个关于连续噪声水平 $\sigma$ 的 ODE。</font>

<font style="background-color:#FBDE28;"></font>

+ **Flow Matching：直接学习“应该往哪里移动”的速度场；**
+ **EDM：学习“当前状态去噪后应该是什么”，再由此构造移动方向。**

| **方法** | **网络主要学习什么** | **跳步的主要原因** |
| --- | --- | --- |
| **DDIM** | **扩散模型的噪声或去噪信息** | **重新构造确定性采样轨迹，跳过部分离散时间步** |
| **EDM** | **连续噪声水平下的去噪器 ****$D_\theta(x;\sigma)$** | **重新设计噪声调度、预条件化和高阶 ODE 求解** |
| **Flow Matching** | **连续时间速度场 ****$v_t(x)$** | **直接积分连续速度场，FM-OT 让轨迹更直** |




# lingbot-vla-2.0；From Foundation to Application: Improving VLA Models in Practice
较第一版的提升：

1.  Generalization across tasks and embodiment
2. Expanded action space in addition to dual-arm hardware platforms（全身控制）
3. Predictive dynamics modeling for improved temporal reasoning.

## 解决的问题
现有 VLA 模型已经能够在若干标准化的双臂操作任务上取得不错效果，但从实验室走向真实应用时仍有三个主要困难：

1. **跨任务、跨机器人泛化能力不足**  
不同机器人具有不同的机械结构、摄像头位置、关节数量和控制接口。一个在双臂机械臂上训练的模型，不一定能迁移到带有头部、腰部、移动底盘或灵巧手的机器人上。
2. **动作空间过于狭窄**  
许多模型主要控制双臂和夹爪，却无法同时控制头部、腰部、底盘和灵巧手。因此，它们难以处理需要“移动底盘—调整身体姿态—双手操作”的全身任务。
3. **缺乏对未来状态的预测能力**  
仅根据当前图像做反应式控制，可能无法判断动作执行后场景会如何变化。例如，机器人要把物体放进抽屉，必须提前估计抽屉、物体和机械臂未来的相对位置，而不是只看当前画面决定下一步动作。

## 前人工作
### 第一类：扩大机器人数据规模
让模型在训练时见过更多机器人、更多任务和更多场景，从而学到更通用的视觉和动作规律。

它们解决了数据覆盖不足的问题，但单纯增加数据并不能自动解决动作接口不统一、全身控制和未来预测问题。

### 第二类：设计跨 embodiment 的架构
另一类工作试图通过统一动作空间或加入 embodiment-aware 模块，使不同机器人能够共享一个模型。

这些方法通常解决的是：

+ 不同机器人动作维度不同；
+ 机器人身体部件不完全一致；
+ 同一个动作在不同机器人上具有不同含义。

不过，已有方法往往针对某一类 embodiment 或某一种结构进行专门设计，未必能同时覆盖机械臂、半人形机器人、全人形机器人和移动操作平台。

### 第三类：引入 latent action 或 world model
还有一些工作引入潜在动作或世界模型，以增强模型对未来状态和长时序任务的理解。

这类方法相比单纯的反应式策略，更强调：

+ 动作会如何改变未来场景；
+ 当前视觉观察和未来状态之间的关系；
+ 长时序任务中的中间状态预测。

### 第四类：使用 Mixture-of-Experts 扩展动作建模能力
Mixture-of-Experts（MoE）方法通过让不同专家处理不同类型的输入或动作模式，提升模型容量和专业化能力。

但过去的 MoE 设计通常会额外引入负载均衡损失，或者预先规定某个专家负责某一种任务、机器人或感知信号。本文认为，对于大规模跨 embodiment VLA 预训练而言，动作中的因素往往是混合的，不适合简单地把专家和某个固定语义绑定。

# 如何解决问题
### 大规模、多机器人、多模态预训练数据
作者收集了约 **90,000 小时机器人数据**，经过清洗后保留约 **50,000 小时高质量机器人轨迹**；同时构建约 **20,000 小时第一视角人类视频池**，最终保留约 **10,000 小时高质量 egocentric 视频**。机器人数据覆盖 **20 种机器人配置**，包括单臂、双臂、半人形、人形机器人以及移动操作平台。

#### 数据清洗也是重要部分
作者并不是简单堆积视频，而是对数据进行较严格的质量控制。例如：

+ 检查动作和状态轨迹的一阶、二阶、三阶变化；（对应速度，加速度，加加速度）检查轨迹的动态连续性
+ 删除速度、加速度或 jerk 异常的轨迹；
+ 删除长时间静止或信号几乎不变化的片段；
+ 检查视频画面和机器人状态是否对齐；（作者使用机器人的 URDF，也就是描述机器人结构、关节和连杆关系的模型，将机器人状态重新投影到图像平面）
+ 删除模糊、遮挡、丢帧以及多视角不一致的视频；
+ 对人类视频过滤掉非第一视角、没有手-物体交互或没有可操作物体的片段；
+ 对手部轨迹进行 SLAM 和人体手部姿态重建，并过滤不连续或违反人体运动约束的轨迹。

#### 已有动作或手部轨迹标签
对于带有动作标签的开源数据集和内部数据，作者进行：

+ 元数据整理；
+ 时间戳对齐；
+ 坐标系转换；
+ 轨迹完整性检查；
+ 转换成标准化手部轨迹格式。

#### 没有动作标签的第一视角视频
对于不带动作标签的视频，作者需要从图像中恢复相机运动和手部运动。

整体过程是：

$$   
\text{第一视角视频} \rightarrow \text{Egocentric SLAM} \rightarrow \text{相机轨迹}  
$$

$$   
\text{视频帧} \rightarrow \text{手部姿态估计} \rightarrow \text{MANO参数}  
$$

$$   
\text{相机轨迹}+\text{手部姿态} \rightarrow \text{世界坐标系中的手部轨迹}  
$$

+ 作者最终把有效的人类手部轨迹存储在世界坐标系中，然后在训练时转换到当前观察帧的相机坐标系。（对应的是相机坐标系）
    - 世界坐标系负责统一存储，当前相机坐标系负责训练时的动作表示。
+ 机械臂的末端使用的是 xyz+四元数

总结：统一质量标准，统一时间关系，统一坐标关系，统一动作接口

## 统一的全身动作表示
为了解决不同机器人动作空间不一致的问题，作者设计了一个 **55 维 canonical action/state representation**。

这个表示包含：

+ 14 维手臂关节位置；
+ 14 维末端执行器位姿；
+ 2 维夹爪位置；
+ 12 维灵巧手关节位置；
+ 4 维腰部位置；
+ 2 维头部位置；
+ 3 维移动信号；
+ 其余维度作为保留维度。（4维）

不同机器人只使用其中适合自身结构的维度，其余维度进行 padding。

## 面向动作专家的无辅助损失 MoE
LingBot-VLA 2.0 在 action expert 中加入 token-level sparse MoE。

它的结构包括：

+ 一个共享专家，用来学习不同机器人和任务之间的通用控制规律；
+ 多个 routed experts，用来学习更具专业性的动作模式；
+ 每个 token 只激活少数几个专家，从而降低计算量；
+ 使用 sigmoid 路由而不是 softmax，使每个 token 可以相对独立地决定与各个专家的匹配程度。

作者采用了**无辅助损失的负载均衡机制**。专家选择由带有 correction bias 的分数决定，而最终的混合权重仍然使用原始路由分数。这样可以把两个目标分开：

+ correction bias 负责避免某些专家过载；
+ 原始 affinity 负责表达模型真正的路由偏好；
+ 不需要额外加入 load-balancing loss 来干扰动作学习目标。

#### softmax 的问题：专家之间存在强竞争
softmax 有一个重要性质：所有专家的概率必须加起来等于 1。

因此，一个专家概率变大，其他专家的概率就必然变小。它们之间存在强竞争。

不利于多专家同时表达不同因素, 在 VLA 中，一个动作 token 可能同时包含多种信息：

对于每一个专家对应的logits输入sigmoid函数，就可以独立计算每一个专家的得分（使用这个的结果选择topk专家） -> 考虑 在选中的专家内部重新归一化，得到最终混合权重。（正常的moe的状态，重新归一化 sigmoid分数）

#### correction bias
选中之后，最终权重 $g_{\ell,j}$ 仍然只使用原始的 $s_{\ell,j}$，不使用 bias。bias 可以改变“谁被选中”，但不能改变“被选中后各专家本来的相对贡献”。

专家 1 过载，专家 3 和专家 4 使用不足，因此当前 bias 为：

$$   
b=[-0.10,\ 0,\ +0.10,\ +0.20]  
$$

更新规则：当前的偏置 - （最近一批数据中专家收到的token数-平均负载）（后项0，表示 当前负载过高，那么偏置将会减小）

用来缓解专家坍塌的问题

+ 传统方法（load balance loss）的问题在于，负载均衡目标和动作学习目标可能发生冲突。可能明明就是该 e1 处理，但是e1负载过高，而e2负载低，而被分配到e2；从学的更好的角度是会被破坏的

## 双查询蒸馏，让模型同时理解当前和未来
这是文章中最核心的机制之一。

作者在视觉和语言 token 中加入两个可学习查询：

+ $Q_t$：表示当前时刻的观察；
+ $Q_{t+T}$：表示动作片段结束或未来时刻的状态。

然后，模型使用两个教师模型进行蒸馏：

1. **LingBot-Depth**：提供几何和深度信息；
2. **DINO-Video**：提供具有时间因果关系的视频表示。

### 当前查询学习什么？
当前查询 $Q_t$ 学习：

+ 当前场景的几何结构；
+ 当前图像中的物体和空间关系；
+ 当前时刻的运动表征。

### 未来查询学习什么？
未来查询 $Q_{t+T}$ 学习：

+ 未来场景的几何状态；
+ 动作执行后可能出现的视觉状态；
+ 未来时刻的动态表征。

深度蒸馏使当前和未来查询分别对齐当前、未来画面的深度特征；视频蒸馏则使它们分别对齐当前和未来时刻的运动感知视觉特征。Dual-Query Distillation

这相当于给模型增加了一个隐式的“动作后果预测”训练目标。它不只问：

现在看到了什么？

还要求模型学习：

如果按照当前任务继续执行，未来场景大致会变成什么样？

这对于需要提前规划的操作非常重要，例如：

+ 把物品放入抽屉；
+ 将物体放进冰箱；
+ 清洁炉灶；
+ 移动底盘后再进行抓取；
+ 需要连续多个操作步骤的长时序任务。

### 相对动作优于绝对动作
相对关节动作的平均成功率为 **55.0%**，绝对关节动作只有 **33.7%**。原因是相对动作的数值范围更小，更像是局部运动修正，而不是直接预测整个机器人的全局关节配置。Relative Actions

### MeanStd 归一化优于其他归一化方法
MeanStd 的平均成功率为 **55.0%**，高于 MinMax 的 **47.5%** 和 Q01–Q99 的 **47.4%**。作者认为，MeanStd 能保留相对动作分布中的较大修正量，而 MinMax 会把大量动作压缩到过窄的范围内。Normalization

### L2 损失优于 L1 损失
L2 的平均成功率为 **55.0%**，L1 为 **46.4%**。对于大量集中在零附近的小幅连续动作，L2 更适合进行精确回归；但在接触丰富、动作分布重尾的任务上，L1 也可能更有优势。（预测的是相对的动作，所以L2 loss会更好一些，相对的动作多聚焦于零附近的小幅度连续修正，适合拟合这种精确分布）；

对于误差更大的情况会给出更大的惩罚，压制大误差可能比单纯减少平均绝对误差更有利于任务成功。 

L2 loss的轨迹更加平滑，L1loss的轨迹会更加细节

+ L1 由于只进行线性惩罚，对异常动作更鲁棒，因此可能更适合接触丰富、噪声大、动作分布重尾的任务。

#### 两种 loss 的核心差异
| 特性 | L1 loss | L2 loss |
| --- | --- | --- |
| 公式 | $ | e |
| 对大误差的惩罚 | 线性增长 | 平方增长 |
| 对异常值的敏感性 | 较低，鲁棒 | 较高，容易受影响 |
| 梯度 | 近似恒定 | 随误差增大 |
| 典型预测目标 | 条件中位数 | 条件均值 |
| 适合的数据分布 | 重尾、含噪、含异常值 | 集中、连续、近似高斯 |
| 控制特征 | 更稳健，不容易被极端动作带偏 | 更重视消除大偏差 |
| 可能的问题 | 接近最优点时不够细腻；梯度在零点不光滑 | 可能被异常值主导；对大误差过度敏感 |


+ **两者都有：使用 Smooth L1 或 Huber loss。**

# WAN
**如何构建一个高质量、功能全面、推理成本可接受，并且真正开放的视频生成基础模型体系**。

**生成式人工智能中的视频生成领域**，更具体地说，是**基于扩散模型和 Diffusion Transformer 的大规模视频基础模型**。

## 解决的问题
传统的视频生成模型通常面临三类问题：

1. **生成质量仍然落后于闭源商业模型**，尤其是在运动幅度、时序一致性、物理合理性和文本遵循方面；
2. **功能比较单一**，多数模型主要支持文本生成视频，难以同时完成图像生成视频、视频编辑、视频延展或个性化生成；
3. **训练和推理成本很高**，模型参数量和视频序列长度都会带来显著的显存与计算压力，普通用户很难运行。
+ 如何让视频生成模型获得更好的画质和运动质量？
+ 如何让同一个基础模型支持多种视频生成与编辑任务？
+ 如何降低训练和推理时的时空计算成本？
+ 如何把模型开放出来，让研究者和普通用户都能使用？

## 前人工作
### **主要采用扩散模型生成视频**
此前的视频生成工作普遍采用扩散模型，将视频压缩到潜空间，然后在潜变量上进行逐步去噪。例如，[Video Diffusion Models](/abs/2204.03458?chatId=01a05bb4-310f-7bc0-9496-837135328fd9) 探索了将扩散建模应用于视频生成，[Stable Video Diffusion](/abs/2311.15127?chatId=01a05bb4-310f-7bc0-9496-837135328fd9) 则通过大规模视频数据训练潜空间视频扩散模型。

在隐空间中进行扩散生成，然后通过vae编码到隐空间，与解码到显式空间

+ 但视频同时包含空间维度和时间维度。随着分辨率、帧数和模型规模增加，注意力计算和显存消耗都会快速增长。

### 通过视频 VAE 降低视频维度
已有模型通常使用 VAE 将视频压缩成低维表示，再在潜空间中训练扩散模型。VAE可以减少扩散模型需要处理的像素数量，但压缩率和重建质量之间存在权衡：

+ 压缩太强，计算量较低，但会丢失纹理、文字和人脸细节；
+ 压缩太弱，重建质量较好，但训练和推理成本很高；
+ 视频还需要建模时间因果关系，否则未来帧的信息可能泄漏到过去帧。

视频 VAE 的三个挑战：时空依赖、高分辨率视频的内存开销，以及时间因果性。

### 主要针对单一任务设计模型
如果每种任务都训练一个独立模型，就会造成：

+ 模型数量多；
+ 部署复杂；
+ 不同任务之间难以共享基础能力；
+ 修改和扩展成本较高。

### 依赖传统指标或简单人工评价
视频生成质量不仅包括单帧画质，还包括运动是否自然、物体是否稳定、摄像机运动是否正确、文本指令是否被遵循等。

## 如何解决问题
Wan的方案可以概括为：

**以一个大规模的文本—图像—视频联合基础模型为核心，再通过专门的 VAE、数据处理、训练策略和任务适配模块，把它扩展成一个多任务视频生成系统。**

### **使用 Diffusion Transformer 和 Flow Matching 构建基础模型**
**W**an采用扩散 Transformer 作为核心生成器，并结合 Flow Matching。作者认为，这种架构已经在大规模图像和视频生成任务中显示出较好的扩展能力。

模型加入了：

+ 文本条件的交叉注意力；
+ 完整的时空注意力；
+ 面向计算效率的结构设计；
+ 1.3B 和 14B 两种规模。

### 提出 Wan-VAE：同时处理空间压缩、时间压缩和因果性
Wan-VAE是文章的关键基础组件之一。它是一种**三维因果 VAE**，同时对视频的时间和空间维度进行压缩。

Wan-VAE将其压缩为大致如下的潜变量：

$$   
[1+T/4,\ H/8,\ W/8,\ C]  
$$

其中潜变量通道数 $C=16$。也就是说，时间维度压缩约 $4$ 倍，空间高度和宽度分别压缩 $8$ 倍。

它的主要设计包括：

+ **3D VAE**：同时建模空间和时间信息；
+ **因果结构**：过去帧不会依赖未来帧；
+ **分块处理和特征缓存**：减少长视频处理时的内存占用；
+ **较高压缩率**：降低后续扩散 Transformer 处理的 token 数量。

### 通过大规模数据处理提升文本和视频对应关系
视频生成模型的能力不仅取决于网络结构，也取决于训练数据质量。Wan设计了数据处理流水线，包括：

+ 视频质量筛选；
+ 图像和视频数据的整理；
+ 自动字幕生成；
+ 密集视频描述；
+ 后训练数据构造。

作者特别强调了 dense video caption，也就是对视频中的动作、摄像机运动、物体类别、颜色、数量、文字、场景、风格和事件等维度进行细致描述。

普通字幕可能只写“一个人在街上跑步”，而密集字幕还可能描述：

+ 人物向哪个方向移动；
+ 摄像机是否跟随；
+ 画面中有哪些物体；
+ 物体的颜色、数量和位置；
+ 场景风格以及运动节奏。

### 通过提示词重写解决训练文本与用户输入之间的分布差异
作者观察到，训练数据中的描述通常很长、很详细，但用户输入的提示词往往只有几个简单词语。这会导致训练分布和推理分布不匹配。

Wan因此使用大语言模型进行 prompt rewriting：

1. 补充场景细节，但不改变用户原始意图；
2. 为主体添加合适的自然动作；
3. 将提示词组织成与训练字幕相似的结构；
4. 在推理时使用 Qwen2.5-Plus 进行重写。

### 统一的图像生成视频框架
Wan-I2V并不是简单地把图片作为文本条件，而是将输入图片编码成条件潜变量，并同时构造一个 mask，显式标明哪些帧是已知条件、哪些帧需要生成。

### 使用 VACE 实现统一视频编辑
Wan还将 VACE，也就是 All-in-One Video Creation and Editing，整合进自身框架。VACE的核心是 **Video Condition Unit，VCU**。

模型可以在同一套输入范式下处理：

+ 视频到视频编辑；
+ 掩码视频编辑；
+ 参考图像到视频；
+ 多参考图像生成；
+ 视频重绘和内容修改；
+ 长视频重渲染。

### 视频个性化生成不依赖额外身份特征提取器
视频个性化通常需要保持人物或物体的身份一致。传统方法常使用人脸识别模型或 CLIP 提取身份特征，但这种方式可能丢失一些细节，例如疤痕、贴纸、遮挡区域或低分辨率人脸。

Wan的做法是不完全依赖外部身份特征提取器，而是直接将输入人脸图像放入 Wan-VAE 的潜空间，并在视频前面添加额外的人脸条件帧，再通过自注意力让模型学习身份信息。



身份信息本身就是一种视觉内容，与其先压缩成一个可能丢失细节的身份向量，不如直接在视频潜空间中保留更丰富的视觉信息。



### Streamer与一致性蒸馏支持长视频和实时生成
标准视频扩散模型通常一次性处理固定长度的视频，视频越长，时空注意力的开销越大。Wan提出 Streamer，通过**滑动时间窗口**生成长视频甚至无限长度视频。Streamer

Streamer的关键机制是：

1. 只在当前时间窗口内进行扩散计算；
2. 缓存前一个窗口的重要 token 或特征；
3. 将缓存信息重新引入下一个窗口；
4. 以较低内存成本保持窗口之间的连续性。

为进一步实现实时生成，Wan将 Streamer 与 [Latent Consistency Models](/abs/2310.04378?chatId=01a05bb4-310f-7bc0-9496-837135328fd9) 和 [VideoLCM](/abs/2312.09109?chatId=01a05bb4-310f-7bc0-9496-837135328fd9) 结合，把原本较多的扩散采样步骤蒸馏成四步一致性模型。

# JEPA：Self-Supervised Learning from Images with a Joint-Embedding Predictive Architecture
## 解决的问题：
传统监督学习需要大量人工标注。例如，要训练一个图像分类器，需要知道每张图片属于“猫”“狗”还是“汽车”。自监督学习则试图从图像自身构造训练信号，让模型在没有人工标签的情况下学习有用的表示。

本文关注的是自监督学习中的一个关键矛盾：

+ 如果模型只学习图像的低层细节，例如像素、颜色和纹理，它可能不具备足够的语义；
+ 如果模型强制不同增强视图具有相同表示，它又可能丢失对局部结构、物体数量、深度等任务有用的信息；
+ 如果直接预测图像中被遮挡的像素，训练成本较高，而且模型容易关注不重要的像素细节；
+ 如果使用大量图像增强或多个视图，计算开销会显著增加。

因此，本文希望学习一种表示，使模型能够理解“图像中有什么、物体处于什么位置和姿态”，同时不必重建所有像素，也不必依赖复杂的人工数据增强。作者提出的方法称为 **I-JEPA（Image-based Joint-Embedding Predictive Architecture）**。其核心思想是：**给定图像中的一个上下文区域，预测同一张图像中其他目标区域的表示，而不是预测目标区域的像素。**

## 前人工作
### 基于视图不变性的方法
这类方法会对同一张图像进行不同的数据增强，例如：

+ 随机裁剪；
+ 缩放；
+ 颜色抖动；
+ 翻转；
+ 生成不同的图像视图。

然后要求这些视图经过编码器后得到相似的表示。典型方法包括 [DINO](/abs/2104.14294?chatId=01a05be5-94d0-7dbd-8452-ff6b28c8ac5b)、[SimCLR](/abs/2002.05709?chatId=01a05be5-94d0-7dbd-8452-ff6b28c8ac5b)、[BYOL](/abs/2006.07733?chatId=01a05be5-94d0-7dbd-8452-ff6b28c8ac5b)、iBOT 等。

这种方法的优点是能够学习较高层次的语义表示。例如，同一只狗经过裁剪、缩放和颜色变化后，模型仍然应该认为它们是同一个对象。

但问题在于，模型被明确要求对这些增强保持不变，而增强本身带有人工先验。不同任务需要的“不变性”并不相同：

（过度的约束会带来损坏）

### 基于像素或 token 重建的方法
另一类方法先遮挡输入图像的一部分，再要求模型恢复被遮挡的内容。

像素重建会迫使模型预测大量低层次细节，这些细节未必是学习高级语义所必需的。

### data2vec 等上下文表征预测方法
[data2vec](/abs/2202.03555?chatId=01a05be5-94d0-7dbd-8452-ff6b28c8ac5b) 已经开始尝试不直接预测像素，而是预测由目标编码器产生的表示。

I-JEPA 与这类工作的不同之处在于：

+ I-JEPA 明确使用多个较大的目标区域；
+ 使用一个空间上分布广泛的上下文区域；
+ 通过预测表示空间中的目标，强调语义结构；
+ 不需要构造多个增强视图；
+ 通过专门的预测器和目标编码器设计提升效率与稳定性。

## 如何解决问题
### 从图像中采样上下文区域和目标区域
对于一张图像，I-JEPA 随机采样：

+ 4 个目标区域，每个区域大约覆盖图像面积的 $15\%$ 到 $20\%$；
+ 1 个上下文区域，覆盖图像面积的 $85\%$ 到 $100\%$；
+ 如果上下文区域与目标区域重叠，则从上下文中去掉重叠部分。

目标区域较大，是为了让模型预测相对完整、具有语义意义的区域，而不是随机的单个像素或小块。上下文区域则要足够大且空间分布充分，使模型能够利用整张图像的结构推断目标区域。

### 上下文编码器只处理可见上下文
上下文区域被送入上下文编码器 $f_\theta$。该编码器是一个 Vision Transformer，负责从可见区域中提取表示。

重要的是，上下文编码器并不处理完整图像，而只处理没有被遮挡的上下文 patch。这样可以减少计算量，也迫使模型根据有限但有信息量的上下文来推断图像中其他位置的内容。

### 目标编码器产生“语义目标”
同一张图像经过目标编码器 $f_{\bar{\theta}}$，得到所有图像 patch 的表示。然后，模型从这些表示中取出目标区域对应的 patch 表示。

这一步与像素重建有本质差别：

+ 像素重建的目标是原始图像中的 RGB 数值；
+ I-JEPA 的目标是目标编码器输出的抽象表示。

### 预测器根据上下文预测目标表示
预测器 $g_\phi$ 接收两类输入：

1. 上下文编码器输出的上下文表示；
2. 表示目标区域位置的 mask token 和位置编码。

它需要预测目标区域中每个 patch 的表示

也就是说，模型不是要求生成一块逼真的图像，而是要求预测出“该区域在表征空间中的含义”。

### 将全局语义和局部空间信息结合起来
许多视图不变性方法倾向于学习全局图像表示，这对分类很有用，但可能损失局部信息。

I-JEPA 同时预测多个局部目标区域，因此不仅学习“这张图是什么”，还学习：

+ 不同区域之间的空间关系；
+ 物体的局部结构；
+ 物体的姿态；
+ 深度和数量等局部视觉属性。

# DreamZero
**机器人基础模型中的泛化问题**：机器人能否在没有见过具体任务、物体、环境甚至机器人本体的情况下，直接执行新的物理操作。作者提出的核心模型是 DreamZero，一种同时预测“未来视频”和“机器人动作”的 **World Action Model（WAM）**。

## 解决的问题
传统机器人策略通常学习一个映射：

$$   
\text{当前观测}+\text{语言指令}\rightarrow\text{机器人动作}  
$$

例如，输入“把苹果放进篮子”，模型根据当前图像和指令，直接预测机械臂下一步该如何移动。

这种方法在训练数据覆盖充分时有效，但存在三个严重问题：

1. **对新动作泛化能力弱**  
如果训练集中没有“解鞋带”，即使模型理解“解鞋带”的语义，也未必知道手应该如何精确运动。
2. **对新环境泛化能力弱**  
物体位置、背景、桌面布局稍有变化，动作就可能失败。
3. **跨机器人本体迁移困难**  
在一种机器人上学到的动作，通常不能直接迁移到另一种机械结构不同的机器人上。

现有模型较擅长回答“要做什么”，但不擅长理解“在真实物理世界中应该怎样做”



Why WAMs. WAMs built upon video diffusion backbones inherit rich spatiotemporal priors from web-scale data, capturing the best of both paradigms: the seamless gradient flow of end-to-end VLAs and dense world modeling supervision for planning. Unlike latent world models (Assran et al., 2025; Hafner et al., 2019, 2020, 2023), which learn dynamics from scratch in compact latent spaces, WAMs leverage pretrained video representations that already encode physical dynamics from internet-scale data. Central to this approach is learning the joint distribution of video and action—DreamZero simultaneously learns both modalities, with video prediction serving as an implicit visual planner that guides action generation. This formulation not only means that improving robotic capabilities reduces to improving video generation, but also enables three capabilities that elude current VLAs: zero-shot generalization to novel tasks, effective learning from heterogeneous robot data, and extremely efficient cross-embodiment transfer from videos. We provide further discussion about the differences between WAMs and alternative world model architectures (e.g., latent-space, 3D point cloud) in Appendix A.

## 前人工作
### Vision-Language-Action 模型：直接预测动作
以 [GR00T N1](/abs/2503.14734?chatId=01a05c3c-935f-7370-b7cd-f8979ce08db9)、[$\pi_0$](https://www.alphaxiv.org/abs/2410.24164) 和 [$\pi_{0.5}$](https://www.alphaxiv.org/abs/2504.16054) 为代表的 VLA 模型，通常将视觉、语言和机器人状态结合起来，端到端预测动作。

它们的优势是：

+ 能利用大规模视觉—语言预训练知识；
+ 能理解物体、指令和任务语义；
+ 对“把可乐罐放到某个位置”这类物体和语义变化具有较强泛化能力。

但它们的主要限制是：**语言和视觉语义知识并不等价于物理运动知识**。模型知道“鞋带是什么”，并不意味着它掌握如何调整手指位置、接触角度和运动轨迹来解开鞋带。论文指出，现有 VLA 的泛化往往集中在物体和语义层面，而不是全新的运动技能和物理环境。VLA Limitations

另一个问题是，VLA 通常依赖较为结构化、重复性较高的机器人示范。每个任务需要收集大量“正确执行”的动作轨迹，数据覆盖范围受到任务数量和人工采集成本的限制。

### 视频世界模型：先预测未来，再生成动作
其核心思想是：

如果模型能够预测“执行某个动作之后世界会变成什么样”，它就能更好地理解动作与物理结果之间的关系。

不过，早期方法中常见的做法是把问题拆成两个模型：（IDM）

1. 视频模型预测未来画面；
2. 逆动力学模型根据未来画面反推出动作。

或者先预测视频轨迹，再在测试阶段通过规划、搜索或优化得到动作。这样做可能带来两个问题：

+ 视频预测和动作预测之间不一定严格对齐；
+ 测试时还需要额外的逆动力学模型或规划过程，增加延迟和系统复杂度。

## 如何解决问题
### DreamZero 的核心处理方式
DreamZero 的核心变化是：

不再只根据当前观测直接预测动作，而是同时预测未来视频和与之对应的动作。

### 模型结构
**时间上自回归，chunk 内部使用扩散/flow matching 生成。**

DreamZero 建立在预训练视频扩散模型之上，使用一个 14B 参数的自回归扩散 Transformer。它接收三类输入：

1. 视觉上下文；
2. 语言指令；
3. 机器人 proprioception，即关节、位置等本体状态。

模型通过不同的解码器同时生成未来视频和动作。训练时，视频 latent 和动作都加入噪声，再通过 flow matching 目标共同去噪。在同一个端到端目标中共同学习

### 创新一：把视频预测和动作预测统一到一个模型中
DreamZero 不采用“视频模型 + 独立逆动力学模型”的简单串联，而是让一个模型联合预测视频和动作。

这样做的意义是：

+ 视频预测提供对物理过程的密集监督；
+ 动作必须解释并实现预测中的视觉变化；
+ 视频和动作在训练过程中保持更紧密的时序对齐。

因此，模型学习的不仅是状态—动作对应关系，还包括连续画面之间的物理演化关系。

### 创新二：用非重复、异质的机器人数据进行训练
DreamZero 的训练数据并不主要依赖每个任务的大量重复示范。以 AgiBot G1 为例，作者收集了约 500 小时数据，覆盖 22 个不同环境，包括家庭、餐厅、超市、咖啡店和办公室；每个 episode 平均约 4.4 分钟，包含约 42 个子任务。Data

作者的假设是：

+ 普通 VLA 只预测动作时，面对杂乱、非重复的数据，很难从噪声较大的状态—动作关系中推断规律；
+ DreamZero 还预测连续视频，因此可以从每一帧之间的变化中学习物理动态；
+ 这样，数据采集可以更多追求任务和环境的多样性，而不是同一任务的反复演示。

### 创新三：采用自回归视频生成和闭环反馈
DreamZero 没有一次性生成很长的视频，而是按 chunk 自回归生成。

每执行完一个动作块，机器人就获得新的真实观测，并用真实观测替换之前预测的视频帧，更新模型的 KV cache。这样可以避免视频预测误差不断累积。

这个闭环结构有两个好处：

1. 模型始终根据最新真实状态重新规划；
2. 生成视频即使存在误差，也不会在很长时间内无限累积。

### 创新四：通过系统优化让 14B 视频模型实时控制机器人
视频扩散模型的主要问题是推理慢。朴素实现中，DreamZero 每生成一个动作块约需 5.7 秒，远远不能满足实时控制需求。Latency

为此，作者进行了多层优化：

+ **CFG 并行**：将条件和无条件推理分布到不同 GPU；
+ **DiT caching**：复用方向相近的速度预测；(类似于fast policy，但是是实时计算相似度是否复用)
+ **Torch Compile 和 CUDA Graphs**：降低 kernel launch 和 Python 调度开销；
+ **低精度量化**：在 Blackwell GPU 上使用 NVFP4；
+ **DreamZero-Flash**：让视频和动作使用解耦的去噪策略。

| 类型 | Query 来源 | Key/Value 来源 | 作用 |
| --- | --- | --- | --- |
| Self-attention | 同一序列 | 同一序列 | 序列内部信息交互 |
| Full self-attention | 同一序列 | 同一序列 | 每个 token 看整个序列 |
| Causal self-attention | 同一序列 | 同一序列 | 每个 token 只能看过去 |
| Cross-attention | 一个序列 | 另一个序列 | 一个模态读取另一个模态 |


需要注意的是，**“self/cross”描述信息来自哪里，“causal/full”描述注意力连接是否受 mask 限制**。这是两个不同维度：

+ self vs. cross：Q、K、V 来自哪里；
+ causal vs. full：哪些位置之间可以连接。

### KV caching
KV caching 缓存 Transformer attention 中过去 token 的：目的在于：自回归生成下，过去的视觉上下文不需要每次重新计算。

## limitation
它的一个明显限制是**高精度操作**。对于需要亚厘米甚至毫米级精度的任务，例如插入、精细装配和精确对齐，宽泛、多样的数据可能不如大量密集重复示范有效。

此外，论文目前主要分别在不同机器人本体上进行预训练，还没有真正完成大规模的多本体联合训练。模型的记忆能力也没有被系统评估，作者暂时没有专门研究那些必须依赖长期记忆才能完成的任务。

### 自回归生成
自回归生成（**autoregressive generation**）是指：**模型按照时间或序列顺序，一步一步生成内容，并把已经生成或已经观测到的内容作为下一步的条件**。

一次生成全部 vs. 一步一步生成

假设要生成未来四帧视频。

非自回归生成：模型一次性输出全部未来帧

自回归生成：

模型按照顺序生成：

$$   
o_1=f(\text{当前观测})  
$$

$$   
o_2=f(\text{当前观测},o_1)  
$$

$$   
o_3=f(\text{当前观测},o_1,o_2)  
$$

$$   
o_4=f(\text{当前观测},o_1,o_2,o_3)  
$$

### 为什么机器人需要自回归生成？
机器人环境是动态的，而且模型无法完全准确地预测未来。

假设机器人要把杯子放进柜子：

1. 模型根据当前图像预测接下来一小段视频；
2. 同时生成对应动作；
3. 机器人执行一部分动作；
4. 真实世界可能和预测不同；
5. 模型读取新的真实图像，再重新预测下一段动作。

这比一次性规划很长的完整轨迹更可靠。

如果一次性生成 20 秒的未来视频和动作，前面哪怕有很小的误差，也可能导致后面完全偏离真实世界。自回归闭环生成则把长任务拆成很多局部决策，每次都根据最新观测纠正。

注意力需要控制为 casual attention，不能看到未来的状态

+ 自回归可以使用KV cache 加速，在自回归生成中，历史上下文不会改变。
+ 可以使用真实的视觉历史，机器人执行完动作后，模型获得新的真实观测。DreamZero 会把预测的视频帧替换为 ground-truth observation，并将真实观测放入 KV cache。
+ 保持视频帧率与动作时间对齐

如果使用双向模型处理一段很长的视频，通常需要把视频下采样，使它和某个任务语言描述对应起来。

例如，一段 10 秒视频中，语言指令只描述第 4 到第 7 秒发生的动作。为了让模型理解对应关系，可能需要对视频进行裁剪或下采样。但这样会破坏原始视频帧率，使视频帧和动作之间的时间对齐变得困难。

自回归模型则可以从任意时刻开始，以原始帧率继续生成

+ 训练的时候使用teacher forcing，使用gt的obs+state+video作为监督或者输入，因为此时不可能有实机数据获取

# Lingbot VA 2.0:Native Video-Action Pretraining for Generalizable Robot Control
这篇文章聚焦于**具身智能与机器人学习中的通用机器人控制问题**：如何训练一个能够理解语言、预测环境变化，并在不同物体、场景、任务和机器人形态之间泛化的机器人操作基础模型。

它提出的核心观点是：**机器人控制不应只是“看到当前图像后直接输出动作”，而应该先预测“接下来世界会怎样变化”，再据此生成动作。**

## 解决的问题
传统 VLA模型更像一个反应式控制器：看到什么就做什么，却没有显式建模动作会如何改变环境。因此，在需要多步操作、持续跟踪物体状态或处理动态环境的任务中，容易出现以下问题：

1. **缺少物理动态建模****：模型知道“物体是什么”，却未必知道“执行某个动作后物体会如何运动”。**
2. **长时序任务容易失去上下文****：例如整理桌面需要连续完成抓取、移动、放置多个步骤。**
3. **对新物体、新场景和新任务泛化能力不足****。**
4. **推理速度不够快****：真实机器人需要高频闭环控制，但视频生成模型通常计算量大、延迟高。**
5. **机器人数据昂贵且有限：如果只依赖机器人示范数据，模型很难获得足够广泛的控制知识。**

文章认为，现有视频-动作模型虽然已经尝试联合预测未来视频和机器人动作，但大多是从通用视频生成模型改造而来：先用面向视频生成的模型预训练，再添加动作模块。这带来了表示空间、因果结构和推理速度上的不匹配。

## 前人工作
### 反应式 VLA 策略：直接从图像和语言预测动作
Vision-Language-Action，也就是 VLA 模型，通常直接根据图像观测和语言指令输出动作。它们可以利用大规模视觉和语言预训练获得较强的语义理解能力，但通常不显式预测未来场景变化。

### 从通用视频生成模型改造视频-动作模型
另一条路线是先训练一个通用视频生成模型，再将其改造成机器人控制模型。例如，[World Action Models are Zero-shot Policies](/abs/2602.15922?chatId=01a060d1-4920-73e6-b058-450e4c6c89d7) （dreamzero）代表了将视频预测与动作预测结合起来的方向，而此前的 [Causal World Modeling for Robot Control](/abs/2601.21998?chatId=01a060d1-4920-73e6-b058-450e4c6c89d7) （lingbot va 1.0）则使用因果世界模型来预测未来视觉状态并生成动作。（但是dream zero使用的不是因果的注意力吗？）

### 只使用机器人数据进行训练
机器人动作数据比网络视频昂贵得多，采集规模和任务多样性都有限。以往工作往往依赖机器人轨迹进行动作学习，而没有充分利用人类操作视频。

## 如何解决问题
从一开始就按照机器人控制的需求，原生预训练一个视频-动作基础模型。（具身原生）

主干用的是 1.0中的MoT结构

### 语义视觉-动作 Tokenizer
传统 VAE 的目标是尽可能重建视频，因此得到的潜变量更关注颜色、纹理和像素细节，不一定适合机器人控制。

LingBot-VA 2.0 使用一个**语义视觉-动作 Tokenizer**，同时优化两个目标：

1. **语义对齐**：让视觉潜变量靠近冻结的视觉基础模型特征；
2. **潜在动作学习**：从连续观测之间的变化中提取紧凑的 latent action。
+ 蒸馏视觉表征，使小型的encoder能够接近大型的视觉模型的能力
+ 同时使用隐式的video token 逆动力学预测动作

视觉状态和动作被放入同一个共享的语义潜空间中，为后续的视频预测和动作预测建立共同表示。这也是它与 [RepWAM](https://www.alphaxiv.org/abs/2606.13674?chatId=01a060d1-4920-73e6-b058-450e4c6c89d7) 等表示学习方向的联系：都尝试从视频中学习更适合动作建模的表示。不过 LingBot-VA 2.0 进一步强调将视觉状态和动作放在同一个、经过视觉语义对齐的空间中，而不是使用纯重建型 VAE 再额外连接动作模块。

### 原生因果视频-动作预训练
LingBot-VA 2.0 使用一个从头训练的**因果扩散 Transformer**，而不是将已有的双向视频生成模型简单改成因果模型。

历史观测与动作 -> 未来视觉状态 -> 实现状态变化所需的动作 

和dream zero直接生成action+video有差别

这种因果结构更符合机器人真实执行过程：

1. 机器人只看到当前及过去的观测；
2. 模型预测可能出现的下一状态；
3. 模型选择能造成该状态变化的动作；
4. 执行动作后获得新的真实观测；
5. 再次进行预测和修正。

因此，模型训练时的结构与测试时的闭环控制结构一致

### Multi-Chunk Prediction，预测多个未来片段
如果模型只预测下一个视频片段，那么相邻片段通常非常相似。此时，模型可能通过复制当前画面来降低损失，却没有真正理解长期动态。

为了解决这个问题，文章提出 **Multi-Chunk Prediction，MCP**。它不仅预测下一个片段，还同时预测未来多个时间跨度：

+ next 1；
+ next 2；
+ next 3。

在训练时，主模型的表示需要支持多个未来时间点的预测，而不是只关注最近的一步。

MCP 强迫模型的内部表示编码更长时间范围内的状态变化，例如：

+ 物体会不会继续移动；
+ 当前抓取是否会导致目标被遮挡；
+ 当前动作是否是长任务中的中间步骤；
+ 场景在未来几步之后会变成什么样。

因此，它改善的是模型的**长期动态建模能力**，有助于长时序操作和多步任务。

值得注意的是，MCP 主要用于训练。部署时可以丢弃这些辅助模块，不增加推理开销；也可以保留它们，用于并行预测未来片段。

# （ICL）in context learning
具身 ICL 的目标不是：

复制人类的手部轨迹。

而是：

从人类视频中提取任务意图和状态变化，再在机器人自身的动作空间中实现这个任务。

机器人任务通常具有明显的**任务条件依赖性**。以“把物体放进容器”为例，机器人需要知道：

+ 哪个物体是目标物体；
+ 哪个容器是目标容器；
+ 物体和容器之间的位置关系；
+ 物体是否需要旋转；
+ 是否要先移动其他物体；
+ 最终物体应处于什么状态；
+ 如果是多个物体，执行顺序是什么。

语言可以描述这些内容，但语言往往存在三个问题。

1. 语言难以完整表达空间信息
2. 语言难以表达连续的状态变化:类视频可以直接展示完整的状态变化过程。
3. 语言难以描述长时序任务

比如“将三个物体按照视频中的顺序分别放入三个容器”。如果只用语言，可能需要详细说明每个物体、每个容器和执行顺序；视频可以直接呈现这种顺序。

因此，Zero-WAM 的出发点是：**在人类视频中，任务目标不是由一句话孤立描述，而是由连续的视觉状态变化来表达。**

**在机器人的ICL中，可能在训练完成之后，输入的信息就不需要包含语言模态，而是 （视觉历史，机器人执行过的历史动作，人类演示视频）就可以生成未来的视频+动作（同时生成或者因果生成）**

**核心是要模型学习到任务层面的对应关系或者说，共性**

使得具身 ICL 可以看成一种跨 embodiment 的条件迁移：

****$ 
\text{Human embodiment} \rightarrow \text{Task semantics} \rightarrow \text{Robot embodiment}
 $

**其中中间的“任务语义”是桥梁。**

### 具身 ICL 中一个非常关键的问题：模型看到上下文，不代表模型真的使用上下文。
如何解决这个问题是核心，即以往的模仿学习，往往只拟合了最影响loss的机器人的动作轨迹，但是并不是根据语言指令或者视觉场景理解得到的结果

**假设训练任务是“把杯子放进盒子”，模型已经看到机器人刚刚抓住了杯子。它可能仅仅依靠短期机器人历史预测下一步**

在训练集内，这个捷径可能有效，因为模型见过“杯子放盒子”任务；但在未见任务上，例如“打开微波炉”，局部历史并不能告诉模型应该打开门、抓住把手还是移动物体。

| **方面** | **普通行为克隆** | **Zero-WAM 具身 ICL** |
| --- | --- | --- |
| 任务接口 | 通常是语言 | 人类视频，也可以加语言 |
| 任务泛化 | 依赖训练任务覆盖 | 通过视频指定未见任务 |
| 输出方式 | 直接预测动作 | 先预测未来机器人视频，再预测动作 |
| 人类数据作用 | 可能作为训练数据 | 作为部署时 task prompt |
| 测试时更新 | 通常不更新 | 不更新参数 |
| 迁移目标 | 直接迁移动作 | 迁移任务语义和未来状态 |


# Zero-WAM: In-Context World-Action Modeling from Human Videos for Open-Ended Task Generalization
聚焦于**机器人操作领域中的“零样本跨任务泛化”问题**：机器人在训练阶段没有见过某个具体任务，部署时也不更新参数，却要根据新的任务说明完成操作。论文提出的核心方案是 **Zero-WAM：让机器人通过观看人类操作视频，在上下文中理解并执行从未训练过的任务**。

## 解决的问题
论文将这种问题定义为**零样本跨任务泛化**，需要满足两个条件：

1. 测试任务在训练阶段没有作为机器人示范任务出现；
2. 测试时不为该任务采集新的机器人数据，也不更新模型参数。

机器人需要学习的是一个**新的任务条件和动作过程**，而不仅仅是识别同一个任务中的不同外观。论文指出，现有 VLA 模型虽然提升了语言条件下的机器人控制能力，但仍然难以弥合视觉语言表征与机器人动作之间的差距。

+ **对于操作任务而言，人类演示视频可能比语言更自然、更完整地表达任务意图。**

## 前人工作
### 第一类：使用语言作为任务接口的 VLA 模型
### 第二类：视频—动作模型
另一条路线是先预测机器人未来会看到什么，再从预测的视频状态中解码动作。

Zero-WAM 沿用了这种思想：模型先生成未来的机器人视频块，再根据这个未来视频预测动作。论文认为，如果模型能够准确预测任务相关的未来视觉状态，动作就可以通过逆动力学从这些状态中解码出来。

### 第三类：把人类视频用于表征学习或策略训练
它们通常把人类视频作为训练数据、视觉先验或适配数据。但这类方法不一定把**一段人类视频直接当作测试时的任务指令**。而且，在野外人类视频通常没有对应的机器人动作标签，因此难以直接监督机器人执行。

### 直接把人类视频作为任务提示
也有工作尝试让机器人观察人类演示后模仿任务

但此前方法通常面临两个限制：

1. 人类视频需要逐任务人工采集，规模不容易扩大；
2. 人类视频与机器人视频之间存在视角、身体形态、动作空间和物体布局差异。

另一些世界动作模型采用测试时适配，例如 [WAM-TTT](https://www.alphaxiv.org/abs/2607.06988?chatId=01a06541-f620-71bb-8733-514af4557434) 会在部署时从人类视频中更新轻量级记忆，[RoboTTT](https://www.alphaxiv.org/abs/2607.15275?chatId=01a06541-f620-71bb-8733-514af4557434) 会通过测试时训练压缩执行历史。这些方法可以处理未见任务，但仍然需要测试时更新或适配。Zero-WAM 的目标则是：**训练完成后，测试时直接看视频并执行，不进行参数更新或测试时训练**。

## 如何解决问题
核心不是让机器人模仿人类的具体手部运动，而是让模型理解：

人类视频展示了什么任务目标和状态变化，机器人应该如何用自己的身体和动力学完成同一个任务。

也就是说，模型学习的是**任务语义层面的对应关系**，而不是逐帧复制人类动作。

## 第一个创新：HumanGen——自动生成大规模人—机器人配对数据
真有点像原子动作分解时根据第一帧图像理解场景，这里是根据第一帧构建人类操作场景

这是论文最重要的数据创新之一。

人工采集一条人类视频，再为它采集一条语义对应的机器人轨迹，成本非常高。论文因此反过来使用已有机器人轨迹自动生成匹配的人类视频。

具体流程是：

1. 从机器人数据集中采样一条轨迹；
2. 使用视觉语言模型分析任务，包括任务名称、初始物体状态、状态变化和最终状态；
3. 编辑机器人视频的第一帧，生成一个人类操作场景；
4. 使用视频生成模型生成从人类视角看到的操作视频；
5. 使用视觉语言模型检查视频是否保持了正确的任务语义和物理合理性；
6. 将合格的人类视频与原始机器人轨迹配对。
+ 关键思想是：**不要求人类视频和机器人视频在外观上完全一致，只要求它们表达相同的任务语义。** 这样模型就会被迫学习“人类视频中的任务目标如何对应到机器人动作”，而不是简单地匹配背景、物体外观或运动轨迹。

## 第二个创新：Task-diverse VA——按任务而不是按轨迹采样
机器人数据集经常存在一个问题：同一个任务被重复遥操作了很多次。例如，一个数据集可能包含大量“把杯子放进盒子”的轨迹，却只包含很少的其他任务。

如果直接按照原始轨迹频率训练，模型会被高频任务主导，数据量变大了，但任务多样性并没有真正增加。

论文因此将数据重新划分为任务，并按照任务进行平衡采样。

它解决的是另一个问题：即使模型使用了人类视频作为任务提示，如果机器人本身没有见过足够多样的机器人动态，也可能不知道怎样把人类视频中的任务目标转换成自己的动作。因此，HumanGen 负责提供丰富的**任务说明**，Task-diverse VA 负责提供丰富的**机器人执行先验**。

## 第三个创新：IFP——让模型真正使用人类视频，而不是走捷径
如果只预测一个视频块，会太短，而无法训练出模型真正理解物理知识或者任务模式；从而无法学习到最根本的，可以用来支持泛化的技能

为此，论文提出 **In-Context Future Chunk Prediction，IFP**。它不只要求模型预测紧接着的下一个视频块，还要求模型从当前表示中预测多个更远的、带时间间隔的未来视频块

IFP 的关键设计是：辅助预测模块**不能直接读取人类视频**。它只能读取主视频 Transformer 已经融合了人类视频信息的中间表示 $\phi$：

这会迫使主分支先理解人类视频，再把“任务未来如何发展”的信息编码到机器人视频表示中。否则，辅助分支就可能绕过主分支，自己直接从人类视频预测未来；这样训练时有帮助，部署时却没有帮助，因为 IFP 模块在推理阶段会被移除。

这正是 IFP 的核心机制：

训<font style="background-color:#FBDE28;">练阶段用远期未来预测监督当前表示，使当前表示必须包含人类视频中的任务演化信息；推理阶段去掉辅助模块，但保留已经学会使用这些信息的主模型。</font>

\right) $

预测k个未来的视频块，然后权重为 0.5，0.25，0.15，0.1？

+ 强制要求视频transformer理解人类视频，生成具有任务演化信息的中间表示

核心的约束为：IFP 模块不能直接读取人类视频 $h$。

它只能读取主视频 Transformer 生成的表示，如果主视频 Transformer 没有理解人类视频，那么 $\phi_{i+1}$ 中就没有足够的任务演化信息，IFP 就难以准确预测远期状态。

# Fast-WAM
**具身智能中的世界动作模型（World Action Models, WAMs）**，核心问题是：**WAM 的性能提升究竟来自训练阶段的视频建模，还是来自测试阶段显式生成未来视频？**

## 前人工作
### **第一类：联合生成未来视频和动作**
**这类方法让视频 token 和动作 token 在同一个生成过程中共同去噪。模型一边预测未来画面，一边预测动作，二者通过共享注意力相互影响。**

优点是视频建模和动作建模联系紧密，但缺点是动作生成会被未来视频生成过程牵制。

### 第二类：先生成未来视频，再生成动作
这类方法采用更明确的“想象—执行”流程

这种方法的问题在于，视频扩散模型通常需要进行多步迭代去噪。机器人控制又要求低延迟，因此显式生成未来视频会带来较高的测试时计算成本。论文指出，传统的 imagine-then-execute WAM 通常需要迭代式视频去噪，但此前并不清楚这些未来视频是否真的对动作预测不可或缺。



对 WAM 进行一个关键的结构性拆分也就是说，Fast-WAM 认为：

+ 视频预测可以作为一种**训练辅助任务**；
+ 但在真正控制机器人时，未必需要把未来视频显式生成出来；
+ 视频建模的主要价值可能在于塑造更好的隐空间表示，而不是提供一段可视化的未来视频。

# <font style="color:rgb(63, 63, 70);">HOST: Robots Acquire Manipulation Skills in Seconds from a Single Human Video</font>
## 解决的问题
传统机器人学习通常采用“收集数据—训练或微调—部署”的流程。要让机器人学会一个新任务，往往需要人工遥操作机器人采集多条示范，再进行离线微调。这一过程不仅耗时、耗费机器人和专家资源，而且更新共享策略参数时，可能导致机器人遗忘原本已经掌握的技能。论文将这种问题概括为三个方面：

1. **数据和时间成本高**：新任务需要多条机器人示范以及数小时的离线微调。
2. **容易灾难性遗忘**：微调新任务可能破坏旧任务能力。
3. **人类视频和机器人执行之间存在巨大鸿沟**：两者在时间速度、身体形态、视角、场景外观和状态空间上都不同，不能简单地把人的动作直接映射成机器人的动作。Problem Setting

**给机器人一段单独的人类视频，它能否在不更新模型参数的情况下，把视频中的操作步骤迁移到自己的身体和环境上？**

## 前人工作
### 一次性视觉模仿：直接把视频作为条件输入
另一类工作研究 **one-shot visual imitation，OSVI**。它们试图让机器人观察一段人类视频，再根据视频执行任务。总体上可以分为两种处理方式：

+ **模块化方法**：先从视频中提取手部姿态、物体关键点、轨迹或目标状态，再把这些信息映射到机器人动作。
+ **端到端方法**：把整段人类视频、当前机器人观测和语言指令输入一个模型，直接预测机器人动作。

有一个问题在于：

:::info
第一，人和机器人的执行速度通常不一样。同一任务中，人可能两秒完成，机器人可能需要十秒，因此视频中的第 $t$ 帧未必对应机器人轨迹中的第 $t$ 步。

第二，人类视频中的状态不能直接作为机器人的执行状态。即使两者处于同一任务阶段，机器人的视角、身体结构、物体位置和外观也可能不同。模型如果直接从高维人类视频预测低维机器人动作，就必须一次性解决“当前处于哪一步”“机器人接下来应该看到什么”“应该采取什么动作”等多个问题。论文将这种困难总结为**时间错位、状态差异以及人—机器人配对数据稀缺**。

:::

### 语言条件的通用机器人策略：零样本执行
近年来的视觉—语言—动作模型可以根据语言指令直接执行大量任务。

## 如何解决问题
HOST 的核心思想可以概括为：

**不直接从“人类视频”预测“机器人动作”，而是先让视频决定机器人应该处于哪个任务进度，再预测机器人自己接下来会看到什么，最后根据这些机器人自身的未来观测生成动作。**

**核心的点在于输入给模型的视频信息是不是实时的（dream zero就是实时的历史信息）**

**这里的点应该是在ICL的时候提供的视频信息？**

### **建立共享任务进度流形**
**HOST 首先使用一个视觉表示模型，把人类视频帧和机器人轨迹帧映射到同一个嵌入空间。然后通过自监督的时间对齐方法，学习两者之间的单调对应关系。**

****

其基本过程是：

1. 对人类视频每一帧生成嵌入： $$   
d_i = f_\phi(o_i^d)  
$$
2. 对机器人轨迹每一步生成嵌入： $$   
r_j = f_\phi(o_j^r)  
$$
3. 根据嵌入之间的距离计算人类帧和机器人状态的相似度。
4. 使用可微分的 Smooth Dynamic Time Warping，以及时间循环一致性，找到两段序列之间的单调对齐路径。
5. 根据视频当前以及即将发生的进度，重新定义机器人应该预测的未来轨迹片段。

这里的关键不是要求人类视频和机器人轨迹在时间上同步，而是要求它们在任务进度上对应。例如，人的“把物体放入盒子”动作可能对应机器人轨迹中持续更长的一段运动；动态时间规整允许两者以不同速度完成同一过程。Task Progress Alignment

因此，HOST 将视频从“被动的条件输入”变成了“主动的目标生成器”：视频展示到哪里，机器人就应该围绕接下来的任务进展生成什么预测目标。

论文明确强调，HOST 的对齐模块不是只把时间对齐作为辅助损失，而是直接用它来构造预测目标。

### 用机器人自己的未来观测作为中间表示
#### 5.1 为什么不直接预测动作？
直接从人类视频预测机器人动作，本质上是在解决一个非常复杂的跨域映射：

$ 
\text{人类视频} \rightarrow \text{机器人动作}
 $

这个映射中间缺少一个重要环节：机器人执行后会看到什么。

### HOST 的三阶段因果结构
和lingbot va有点类似

$ 

\text{视频进度} \rightarrow \text{机器人未来观测} \rightarrow \text{机器人动作}

 $

### 两阶段训练
1. 第一阶段：机器人—机器人配对训练

从已有机器人数据集中，把同一任务的不同机器人执行轨迹配成对。模型首先学习：

+ 如何跟随另一个执行过程；
+ 如何预测机器人未来的视觉状态；
+ 如何根据未来状态生成动作；
+ 如何在不同执行速度之间进行任务进度对齐。

因为两段轨迹都是机器人数据，跨身体和跨视角的差异较小，模型较容易学到任务进度和未来状态预测能力。

2. 第二阶段：少量人类—机器人配对适配

然后使用相对较少的人类—机器人配对示范，把模型从“机器人视频条件执行”扩展到“人类视频条件下的机器人执行”。这样，昂贵的人—机器人配对数据只承担跨域适配作用，而不是从头训练整个能力。
