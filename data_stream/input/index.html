    Input 传感器输入层 (src/inputs)¶

    文件路径：src/inputs/（含 68 个插件）

    MAGIC 的感官系统。每个 Input 插件负责一类数据源——从机器人硬件到外部 API——将其统一转换为 LLM 可读的自然语言文本。

    与 Background 层（驱动传感器持续运行的守护线程）不同，Input 层负责读取并翻译：从 Provider 拿原始数据 → 转为自然语言 → 注入 IOProvider → 拼入 LLM prompt。

    类继承体系¶

    Sensor (异步迭代器基类)
  │
  ├── listen()          → async iterator，yield 原始数据
  ├── raw_to_text()     → 原始数据 → Message (timestamp + text)
  ├── formatted_latest_buffer() → 格式化输出 + 注入 IOProvider
  └── stop()
        │
        ▼
FuserInput (加 _poll() 循环)
  │
  ├── _listen_loop()    → while True: yield await self._poll()
  ├── _poll()           → 子类实现：异步轮询数据源
  └── _raw_to_text()    → 子类实现：原始数据 → Message

    Sensor 基类¶

    class Sensor:
    async def listen(self) -> AsyncIterator[R]:
        """异步迭代器，yield 原始数据事件"""
        async for event in self._listen_loop():
            yield event

    async def raw_to_text(self, raw_input: R):
        """原始数据 → 追加到 Message 缓冲区"""

    def formatted_latest_buffer(self) -> str | None:
        """取最新缓冲区消息 → 格式化 → 注入 IOProvider → 返回"""

    def stop(self):
        """清理资源"""

    FuserInput — 添加轮询循环¶

    class FuserInput(Sensor):
    async def _listen_loop(self) -> AsyncIterator[R]:
        """默认：死循环轮询"""
        while True:
            yield await self._poll()

    async def _poll(self) -> R:
        """子类实现：从数据源拉取下一次数据"""
        raise NotImplementedError

    一个 Input 的生命周期¶

    以 UnitreeGo2Odom 为例：

    InputOrchestrator.start()
    │
    ├── 为每个 Input 创建 asyncio Task
    │
    └── _listen_to_input(unitree_go2_odom_input):
          │
          async for event in input.listen():      ← _listen_loop: while True: yield _poll()
          │   │
          │   └── _poll():                        ← 每 0.1s 触发一次
          │         return self.odom.position     ← {x, y, yaw, moving, body_attitude...}
          │
          └── await input.raw_to_text(event):     ← 原始 dict → 自然语言
                │
                {"moving": True, "body_attitude": STANDING}
                  → Message("You are moving - do not generate new movement commands.")
                  → 追加到 self.messages 缓冲区

    每个 tick，主循环调用 formatted_latest_buffer()：

    def formatted_latest_buffer(self) -> Optional[str]:
    latest_message = self.messages[-1]
    result = f"\nINPUT: {self.descriptor_for_LLM}\n// START\n{latest_message.message}\n// END\n"
    self.io_provider.add_input(self.descriptor_for_LLM, latest_message.message, ts)
    self.messages = []
    return result

    输出格式（最终拼入 LLM prompt）： 

    INPUT: Information about your location and body pose...
// START
You are moving - do not generate new movement commands.
// END

    核心设计模式¶

    模式 1：Provider 拉取型（最常见）¶

    Input 不直接访问硬件，而是调用 Provider 单例拿数据：

    class UnitreeGo2Odom(FuserInput):
    def __init__(self, config):
        self.odom = UnitreeGo2OdomProvider(...)   # Provider 单例
        self.descriptor_for_LLM = "Information about your location..."

    async def _poll(self):
        await asyncio.sleep(0.1)
        return self.odom.position                  # 从 Provider 读取

    async def _raw_to_text(self, raw):
        if raw["moving"]:
            return Message(ts, "You are moving - do not generate new movement commands.")
        ...

    Provider（Background 驱动）→ Input（读取 + 格式化）→ IOProvider + LLM prompt

    模式 2：自驱动型（ASR / VLM）¶

    Input 自己管理完整的采集管线，不依赖外部 Provider：

    class QwenRealtimeASRInput(FuserInput):          # ~1100 行
    def __init__(self, config):
        # 自己管理麦克风、唤醒词检测器、WebSocket 连接
        self._wake_detector = SherpaOnnxKeywordDetector(...)
        self._audio = pyaudio.PyAudio()
        ...

    async def _listen_loop(self):
        # 不走 _poll()，直接覆盖 listen 逻辑
        # 麦克风 PCM → 唤醒词 → ASR WebSocket → 转录文本

    模式 3：文件/API 读取型¶

    直接读文件或调外部 API：

    class AutonomyLocationsInput(FuserInput):
    async def _poll(self):
        await asyncio.sleep(0.5)
        locations = json.loads(Path(self.config.locations_file).read_text())
        return "\n".join(
            f"{name} (x:{pose[0]:.2f} y:{pose[1]:.2f})"
            for name, poses in locations.items()
        )

    InputOrchestrator — 并发管理¶

    class InputOrchestrator:
    async def listen(self):
        # 所有 Input 并发运行，互不阻塞
        input_tasks = [
            asyncio.create_task(self._listen_to_input(input))
            for input in self.inputs
        ]
        results = await asyncio.gather(*input_tasks, return_exceptions=True)
        # 一个 Input 崩溃不影响其他，错误只记录日志

    async def _listen_to_input(self, input: Sensor):
        async for event in input.listen():           # 异步迭代原始事件
            await input.raw_to_text(event)           # 原始→文本→缓冲区

    关键设计： - 并发隔离：每个 Input 独立 asyncio Task，互不阻塞 - 错误隔离：return_exceptions=True 保证一个 Input 崩溃不影响其他 - 异步迭代：async for event in input.listen() 统一接口，无论底层是轮询还是 WebSocket

    与 Background 层的关系¶

    Input 层 Background 层
    运行方式 asyncio 并发，每个 tick 被主循环调用 formatted_latest_buffer() 独立线程池，while True: run() 持续运行
    职责 读取 Provider 数据 → 格式化为 LLM 可读的自然语言文本 驱动 Provider → 让传感器持续产出数据
    类比 翻译官（传感器原始数据 → 自然语言） 引擎（驱动硬件持续运转）
    输出 拼入 LLM prompt 的 INPUT: 段 更新 Provider 内部缓存

    简言之：Background 让数据"有得读"，Input 负责"读出来并翻成 LLM 能懂的话"。
