    Provider 全局服务层 (src/providers)¶

    文件路径：src/providers/（65 个文件）

    基础设施层，以单例模式提供全局服务——传感器驱动、硬件状态、通信通道、LLM 上下文管理等。

    每个 Provider 以线程安全的单例（Singleton）形式存在，输入/动作/后台任务都通过它们读写全局状态，是整个系统的"血管系统"。

    核心设计模式¶

    所有 Provider 通过 singleton.py 的线程安全装饰器保证全局唯一实例：

    ┌────────────────────────────────────────────────────┐
│                  MAGIC 运行时                       │
│                                                     │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐             │
│  │ Input   │  │ Action  │  │Background│  ...       │
│  │ 插件     │  │ 连接器   │  │ 执行器   │            │
│  └────┬────┘  └────┬────┘  └────┬────┘             │
│       │            │            │                   │
│       └────────────┼────────────┘                   │
│                    ▼                                │
│  ┌─────────────────────────────────────┐           │
│  │         IOProvider (单例)            │           │
│  │  _inputs: Dict[str, Input]          │           │
│  │  _tick_counter: int                │           │
│  │  _variables: Dict[str, Any]        │           │
│  └─────────────────────────────────────┘           │
│                    │                                │
│       ┌────────────┼────────────┐                   │
│       ▼            ▼            ▼                   │
│  D435Provider  ConfigProvider  ContextProvider      │
│  (单例)         (单例)          (单例)               │
│                                                     │
│  所有单例通过 @singleton 装饰器保证全局唯一            │
└────────────────────────────────────────────────────┘

    # singleton.py — 线程安全单例
@singleton
class IOProvider:
    def __init__(self):
        self._lock = threading.Lock()
        self._inputs: Dict[str, Input] = {}
        self._tick_counter: int = 0
        ...

    1. 核心基础设施¶

    文件 类 作用
    singleton.py @singleton 线程安全单例装饰器，所有 Provider 的基石
    io_provider.py IOProvider ★ 全局 I/O 总线：输入存储、tick 计数、动态变量、LLM/Fuser 时间戳
    context_provider.py ContextProvider 通过 Zenoh 广播模式感知上下文（om/mode/context topic）
    config_provider.py ConfigProvider 运行时配置服务：Zenoh 接收 get/set config 请求（om/config/request → om/config/response）
    function_call_provider.py LLMFunction / FunctionGenerator 装饰器 + 工具：将 Python 方法自动转换为 OpenAI function-calling schema

    IOProvider — 全局黑板¶

    IOProvider.add_input(key, value, timestamp)   # 传感器写入
IOProvider.get_input(key)                      # 决策层读取
IOProvider.increment_tick()                    # 每周期 tick+1
IOProvider.add_dynamic_variable(key, value)    # 跨模式共享变量

    ConfigProvider — 运行时配置热更新¶

    远程客户端                                     MAGIC 运行时
    │                                              │
    ├── Zenoh publish "om/config/request" ──────▶ ConfigProvider
    │   {request_id, config: new_json5}           │
    │                                              ├── 写入 config/memory/.runtime.json5
    │                                              └── 发布 "om/config/response"

    LLMHistoryManager — 对话历史自动摘要¶

    当历史消息超过 history_length 时，自动用 LLM 将旧消息压缩为摘要，保持上下文窗口在限制范围内：

    [摘要] [动作] [新的传感器输入] [LLM输出的动作]
   ↑                            ↑
   保留                          新消息 ← 超出限制时触发摘要

    数据流向示例¶

    一次完整 tick 周期中各 Provider 的协作：

    Tick N 开始
    │
    ├── IOProvider.increment_tick()          # tick = N
    │
    ├── Input 线程 (后台):
    │   ├── UnitreeGo2OdomProvider → DDS 读取里程计
    │   │   └── IOProvider.add_input("UnitreeGo2Odom", xyz_yaw_str, ts)
    │   ├── D435Provider → 读取 RGB-D
    │   │   └── IOProvider.add_input("D435RealSenseInput", vision_text, ts)
    │   └── QwenRealtimeASRInput → 语音转录
    │       └── IOProvider.add_input("Voice", transcript, ts)
    │
    ├── LLM Cortex:
    │   ├── 读取 IOProvider.inputs (所有 sensor 数据)
    │   ├── LLMHistoryManager.update_history()  # 管理上下文窗口
    │   ├── 调用 LLM → 输出 Actions
    │   └── ContextProvider.update_context(...)  # 广播模式上下文
    │
    ├── Action 执行:
    │   └── ConfigProvider 提供运行时配置参数
    │
    └── LLMHistoryManager:
        ├── 记录本轮输入+输出到 history
        └── 超 history_length → 启动后台摘要任务

    架构要点¶

    1. 单例模式 — 所有 Provider 通过 @singleton 保证全局唯一，任何模块 import 即获得同一实例
    2. 线程安全 — singleton.py 用 threading.Lock 保护构造；IOProvider 内所有读写都持锁
    3. Tick 驱动的时效性 — 每个输入带 tick 标记，evaluate_action_gate_input_freshness() 可以判断输入是否"新鲜的"
    4. 多平台 — 里程计/导航/VLM 都有平台特定实现（Go2 / G1 / K1 / TB4 / Tron / UBTech），共用基类
    5. 解耦 — Provider 间通过 IOProvider 黑板模式沟通，不互相直接调用
    6. 自动历史管理 — LLMHistoryManager 超出长度时自动摘要压缩，LLM 始终在上下文窗口内推理
